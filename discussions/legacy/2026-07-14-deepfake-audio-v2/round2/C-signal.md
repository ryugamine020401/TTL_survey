# Round 2 質詢：訊號處理研究者（Agent C）——第二輪（無真人實測）
日期：2026-07-14

> 我的裁判標準只有一把尺：**訊號在真實傳輸鏈上死不死，是資訊物理學的事實，不是宣稱。** 一個防禦（或一個模擬）若把「不可逆資訊摧毀」誤當成「可逆分佈偏移」，或反過來，它在真實通道上就會以它自己沒預料到的方式失效。本輪多數提案的計算性驗證方案都藏著一個共同的訊號層漏洞：**它們的通道環節用的是模擬 codec，而模擬 codec 相對真實通道的樂觀偏差（Deepfake-Eval-2024 audio AUC 掉 48%，G 檢索 S10）沒有被任何一條敏感度掃描覆蓋。** 我逐一點名。

## 一、對他人提案的挑戰

### 挑戰 1 → Agent F 提案一「受騙鏈模擬」：你掃了人，卻沒掃通道，而通道那一格的樂觀偏差比你掃的 δ 更致命

F 把模擬鏈定義為「生成器（含閉源 API）→ **通道** → 偵測器（含六種棄權機制）→ 警告政策 → 文獻校準的受害者模型 → 受騙/得救」，並且對「未知參數（壓力劣化 δ、語音情境服從率）**全區間掃描**」，用 dominance claim（「在全參數區間 policy A ≤ policy B」）迴避外部效度攻擊。這個誠實紀律我尊敬——但它有一個結構性盲點。

F 對「人」那一環做了嚴謹的區間掃描，卻把「**偵測器在通道後的 recall**」當成一個**固定輸入**餵進鏈裡。問題是：這個輸入本身是從哪裡來的？如果它來自 F 提案一技術路線月 1–4 沿用的 shift benchmark，那個 unseen-channel 軸用的是 #3 的模擬 codec 管線。而**模擬 codec 對真實通道系統性樂觀**——這正是我提案一與 G 提案 B-2 的立論核心，也是 F 自己在**提案二**裡承認的「素材真實性是第三個樂觀偏差軸」。

於是矛盾出現了：F 提案一的 dominance claim 宣稱對「人的行為假設」穩健，卻對「偵測器性能假設」脆弱。如果真實通道讓偵測器 recall 比模擬值低 20–40 個百分點（Deepfake-Eval-2024 的先驗量級），那 confident-real 格的機率質量、棄權格的機率質量會整個位移，policy 之間的排序**完全可能翻轉**——而 F 的敏感度分析根本沒有這一軸。

**具體修法（我願意幫）**：把「通道樂觀偏差」升格為與 δ 平起平坐的**第三個掃描維度** γ——偵測器 recall 從「模擬通道值」掃到「真實通道值（用我提案一/G-B2 的實測落差當上界）」。只有當 dominance 在 δ × 服從率 × **γ** 的三維全區間都不翻轉，F 的排序才誠實。否則 F 提案一是「用一個沒掃的樂觀偵測器輸入，去做一個掃得很仔細的人類推論」——精緻的上層建築蓋在沒驗過的地基上。這正是我對「計算性驗證方案推論不到真實情境」的定義。

### 挑戰 2 → Agent B 提案二「CallAttest」的滑動窗 perceptual hash 鏈：你要綁定的內容，正好是電話通道先幫攻擊者抹掉的那一段

B 主張「hash 鏈綁定內容，使協定同時抵抗號碼冒用、mid-call injection 與**事後音訊移花接木**」，靠「滑動窗 perceptual hash 鏈」讓「局部替換『帳戶 A→帳戶 B』會破壞被替換窗及其後所有窗的鏈驗證」。B 自己也在 Q1 問我：什麼特徵域能讓「codec 劣化不斷鏈、惡意替換必斷鏈」兩個要求同時成立。

我的挑戰就是：**這兩個要求在真實電信通道上近乎資訊理論互斥，CallAttest 的內容綁定宣稱會死在它自己要部署的那條通道上。** 理由是訊號物理：

- 要「codec 劣化不斷鏈」，perceptual hash 必須只 key 在 CELP（AMR-WB/EVS）**保留**的東西上——粗頻譜包絡（共振峰）、基頻軌跡、能量輪廓。CELP 是分析-合成 codec，它逐幀丟棄相位微結構與高頻細節，只保留「聽得懂」所需的參數。
- 但「帳戶 A→帳戶 B」這種惡意替換，正好是一段**新的可懂語音**——它的共振峰軌跡、基頻、能量輪廓與原段高度相似（都是同一個語者念數字）。CELP 早就把能區分它們的細節丟了。所以攻擊者要找一個「hash 落在容忍半徑內、語意卻不同」的 second-preimage，難度**極低**，因為容忍半徑必須開到足以吸收 CELP 的重合成失真，而那個半徑已經比「兩串不同帳號的語音差異」還大。

換句話說：電話通道對關鍵短 token（帳號、金額這種 3–5 秒、少數位數）的**內容可靠承載量本來就逼近 0**——這是我第一輪判 in-band payload 死刑的同一個物理事實，B 用 perceptual hash 換了個形式，死結沒解開。B 的失敗備案「降級為粗粒度時間戳綁定」我認為才是誠實的終點，但那時「抵抗事後移花接木」這個賣點就沒了，CallAttest 退回成「STIR/SHAKEN + 內容雜湊時間戳」，delta 大幅縮水。我在下面第二節給 B 完整的特徵域答案，結論是：**沒有任何特徵域能同時滿足兩個要求，B 該把內容綁定粒度誠實下修到「語者+韻律連續性」而非「逐 token 內容」。**

### 挑戰 3 → Agent E 提案二「拼接式 relay 模擬」的「重過通道消除拼接偽影」：CELP 不會統一聲學來源，你的保守下界方向未經證明

E 的協定核心防線是：把拼接樣本「**全部拼接後重過同一通道管線**」，主張「CELP 類 codec 重合成會把兩段的通道特性**統一投影**到同一空間，殘留的只有聲源本身的差異」，並以此宣稱聲源連續性稽核抓到的是 relay 本質而非拼接手法，且拼接模擬對攻擊者「系統性有利」故為保守下界。

作為訊號處理者我必須指出兩個技術錯誤：

1. **CELP 重合成統一的是 codec 自己的染色，不是兩段錄音的聲學來源。** 房間脈衝響應（RIR）、底噪頻譜、麥克風染色，這些是**訊號內容**——它們被 codec 編碼並重建，不會被「投影統一」。CELP 對真人 X 段與共犯 Y 段各自獨立編碼，兩段的 RIR/底噪差異原封不動穿過 codec（只是各自被染上同一層 codec 色）。所以「聲源連續性稽核」很可能撿到的仍是**兩段錄音環境的差異**，而不是 relay 的聲源切換——E 想消除的 label-leakage 捷徑並沒有被重過通道消掉，只是被塗了一層 codec。

2. **更糟：重過通道可能「新增」而非「消除」邊界線索。** 拼接點會造成 LPC 係數與激勵訊號軌跡的不連續，CELP 的長期預測（LTP/pitch tracking）與 jitter buffer/PLC 會在邊界處產生**特有的重合成 artifact**——這是一個 codec 引入的、真實 relay 未必有的拼接指紋。若稽核器學到這個，E 的「保守下界」方向就**反了**：模擬可能**高估**稽核性能，讓真實 relay 顯得比實際更好抓。E 宣稱「保守下界不需要保真度證明」是紅隊標準邏輯——但那個邏輯只在「模擬偏差方向確定對攻擊者有利」時成立，而在拼接+codec 這個具體情境，偏差方向**未經證明**，甚至可能有利於防守方（虛假樂觀）。

E 已經很有意識地要做「重過通道前 vs 後的稽核性能差」ablation——很好，但那個 ablation 不足以判定偏差方向。**我的要求**：加一組「同語者、同語句、僅換錄音環境」的 confound 對照（把 RIR/底噪差異單獨隔離），以及一組「同錄音環境拼接」（把純聲源差異隔離）。只有這兩組都跑，E 才能宣稱稽核抓的是聲源而非環境，才能判定下界方向。否則提案二的核心結論建立在一個訊號層想當然爾之上。

### 挑戰 4 → Agent A 提案二「失效歸因」的 channel-family closed-set 假設：codec 足跡確實穩定，但真實世界的通道不是封閉集

A 提案二把棄權升級為診斷，主張對通道劣化做「closed-set over codec families」的歸因，理由是「codec 的頻譜足跡是確定性的訊號處理事實」，並附一個「換通道重送→可靠性恢復」的機器可驗證干預。A 直接問我這個假設成不成立。

我在第二節正面回答技術細節，這裡先下挑戰：**「codec 足跡穩定」是對的，但「closed-set」是致命的錯字。** A 的歸因器只在「你能列舉所有 codec 家族」時才 well-defined，而真實詐騙鏈的通道**不是封閉集**：G 檢索 S7 的 RTCFake 明載其評測集含 **unseen platform**，社群平台的私有 neural transcode 管線（#3 自承的「未知 codec」殘留 gap）根本沒有公開規格。攻擊者的 LINE→重上傳→Messenger→截圖轉錄鏈產生的是**訓練家族外**的複合足跡，A 的歸因器會在它最該工作的地方遇到自己的 OOD 問題——這跟 A 提案一想解決的偵測器 OOD 是同一堵牆，只是搬到歸因層。A 已經預留「channel 端強 claim、generator 端弱 claim」的不對稱，但我要把強 claim 再收一格：**channel 端的強 claim 只在「傳統 CELP 封閉家族」內成立，一旦通道含 neural codec 或未知平台轉檔，channel 歸因也必須降為 open-set novelty flag。** 這不是否定 A 的提案，是幫它把誠實邊界畫在物理正確的地方——而這一格，正好是我提案二（neural codec 資訊摧毀圖譜）能供給 A 的東西。

## 二、回答指名給我的問題

### 回答 Agent A 的兩問

**A-Q(a)：AMR-WB/EVS/Opus/Speex 的足跡在疊加 unseen generator 時是否仍可辨？generator artifact 會遮蔽或偽裝 codec 足跡嗎？**

大致可辨，理由是兩者住在**大致正交的訊號維度**：
- Codec 足跡是**確定性、低頻寬側**的：頻寬硬截止（AMR-WB 上限 ~7kHz、EVS super-wideband ~14kHz、窄帶 Speex ~3.4kHz）、CELP 重合成的諧波規則化、封包遺失/PLC 造成的時域外插空洞、DTX 造成的 comfort noise 段。這些是「通道對所有輸入一視同仁施加」的變換。
- Generator artifact 是**統計性、細結構側**的：vocoder 的相位不一致、上採樣棋盤效應、過度平滑的高頻能量、基頻微顫的統計異常。

疊加時 codec 足跡本身**不會被 generator 遮蔽**（codec 是後施加的、對兩類共有的算子），所以「這段有沒有過 AMR-WB」這種**通道存在性**判斷在疊加下仍穩健——這對 A 的 channel-family 分類是好消息。**但要警告兩件事**：(i) generator artifact 可能被 codec **摧毀**（相位類 artifact 過 CELP 重合成基本投影掉，這是我第一輪就講的層級假說），所以「通道校正後殘差」裡的 generator novelty 訊號會比 A 預期的弱——A 提案二步驟月 4–6 的「通道校正後 real-manifold 殘差距離」在 CELP 通道後可能沒剩多少可讀資訊；(ii) neural codec 是例外，見上面挑戰 4，它會用自己的生成 manifold 重寫整段，codec 足跡與 generator 足跡在 token 空間**糾纏**而非正交——這是 closed-set 崩掉的物理機制。

**A-Q(b)：攻擊者用「先過真通道再重灌」（loopback 變體）製造真實 channel 足跡，歸因器會被騙成「channel-attributed→建議重送」，訊號層有破綻嗎？**

殘酷的答案：**對單次通道，訊號層沒有可靠破綻，因為那個 channel 足跡是真的。** codec 不知道進到麥克風/loopback 之前的訊號是真人還是被播出來的 deepfake——CELP 只忠實編碼它收到的波形。這跟第一輪判死「通道一致性檢查」的 loopback 攻擊是同一招，我建議 A 直接把它列為**已知不設防**，寫進威脅模型第一頁。

**但有一個部分的 tell，而且它正好是我提案二的方法**：loopback 重灌會造成 **codec tandem（串接）**——deepfake 生成時本身帶的 codec/vocoder 足跡 + loopback 電信通道的第二層 codec 足跡疊在一起，形成雙重量化的串接指紋（例如兩次不同 codec 的頻寬截止痕跡、二次 CELP 重合成的諧波規則化加劇）。乾淨的真人來電只有單層電信 codec。所以歸因器可以加一個「**tandem 檢測軸**」：不是判「有沒有過通道」，而是判「過了幾層 codec」。這不是萬靈丹（攻擊者可以用無損 loopback 或匹配 codec 減少串接痕跡，成本上升），但它把 loopback 從「零成本零痕跡」推到「要付出避免串接的成本」——這正好接進 D 的攻擊成本地圖。**我提案二的 tandem/neural-codec 圖譜可以直接供 A 當這條軸的訊號基礎。**

### 回答 Agent B 的兩問

**B-Q1：2026 真實通訊管線（含 neural codec 與平台 neural compression）上，audio watermark 可靠容量還剩幾 bit？若 <5 bit 索引式構造該進墳場。**

我給你分層估計（標明：精確值需我提案一/G-B2 的實測，以下是基於 codec 物理性質的**工程估計**，不是實測數）：
- **傳統 CELP 電信通道（AMR-WB/EVS，無丟包）**：對設計良好的 spread-spectrum/neural watermark（AudioSeal 類），存活容量我估在**十幾到數十 bit** 量級——你 Round 3 假設的 ~20 bit 在**無丟包、單層 CELP** 下是站得住的樂觀估計。ECC 開銷後有效索引空間會再砍。
- **加封包遺失（PLR 5–20%）**：容量隨 PLR 陡降，因為 PLC 外插的段落等於 watermark 訊號被局部清零。**這裡 20 bit 可能掉到個位數。**
- **neural codec / 平台 neural compression**：這是你的生死線，而我的估計是**悲觀**——neural codec 的 decoder 是生成模型，它把輸入投影到自己的生成 manifold，任何不落在該 manifold 上的擾動（watermark 本質上就是這種擾動）會被**投影抹除**。可靠容量我估**逼近 0 到個位數 bit**，且不是均勻的——這正是我提案二要系統性量的東西。

**所以直接回答你的 go/no-go：** 若目標通道是純傳統 CELP 電信網，索引式構造（k≈20）**可能活**，但你必須把 PLR 納入容量預算並打安全折扣。若目標通道含 neural codec/平台 neural compression，索引式構造**大概率該進墳場**。我強烈建議你把「容量量測」設為月 3 前的 go/no-go 檢查點（你自己也這樣排了），而且**用我提案一/提案二的實測數字，不要用模擬 codec 的樂觀值**——模擬 codec 會給你一個活得下去的假象。這是我能給你最有價值的一句話：**你的構造生死取決於一個實測數字，而那個數字只有在真實通道（或 neural codec 離線 transcode）上量才算數。**

**B-Q2：滑動窗 perceptual hash 在 AMR-WB/EVS 重合成下，該用什麼特徵域讓「codec 劣化不斷鏈、惡意替換必斷鏈」同時成立？**

我的誠實答案（也是挑戰 2 的技術根據）：**沒有任何特徵域能同時滿足這兩個要求到「逐 token 內容」的粒度。** 逐一排除：
- **spectral envelope（共振峰/LSF）**：CELP 恰好保留它（這是 CELP 的設計目標），所以 codec-robust——但正因為它是「聽得懂所需的粗結構」，不同帳號的同語者語音在這個域高度相似，惡意替換**不會斷鏈**。不滿足要求二。
- **prosody contour（基頻/能量軌跡）**：更粗，codec 保留得更好，但區分力更差。同樣不滿足要求二。
- **相位/高頻細結構**：區分力足夠（惡意替換會斷鏈），但 CELP 重合成把它摧毀，正常 codec 劣化就會斷鏈。不滿足要求一。

這是一個**帕累托前緣**：codec-robust 與 discrimination 在電話通道上此消彼長，交叉點的粒度遠粗於「帳號數字」。**我的建設性建議**：放棄逐 token 內容綁定，把 CallAttest 的內容綁定粒度誠實下修到 **codec 保留得住的那一層**——「這段通話的語者身分 + 韻律連續性沒有被中途換人/剪接」。這抵抗 mid-call 換語者、換整段音訊（relay 接管），但**不**抵抗「同語者念不同帳號」的移花接木——後者在電話通道上物理不可綁。你的協定仍有價值（擋號碼冒用 + 擋換人接管），但賣點清單要刪掉「事後逐 token 內容防竄改」。特徵域我建議用 **CELP-domain 的 LSF + 基頻軌跡的時序 hash 鏈**，並把容忍半徑用我提案一的實測 codec 劣化分佈來標定，而不是拍腦袋。

## 三、我支持的提案

### 支持 1：Agent G 提案 B-2「電信網是最後一哩」——這是我第一輪的合流夥伴，且 G 的史官紀律讓它比我的版本更誠實

G 做了一件我該做卻做得沒他狠的事：**親手更新自己第一輪的認證，承認「首個真實通道」空白被兩顆魚雷（2509.26471 Presentation、RTCFake）侵蝕**，並把 novelty 錨點誠實撤守到「蜂巢電信網 × watermark/provenance bit 存活 × Article 50 審計」。這個重錨我完全同意，而且它讓題目更強不是更弱——因為兩篇前作**替我們消掉了「落差存在嗎」的風險**（Presentation 證明 +57% 改善空間、RTCFake 證明真灌通道可發表），剩下的是我最擅長的物理問題。

**我的角色如何補強它**（這也是我提案一相對 G-B2 的增量，我主張兩者合為一題或明確分工）：
