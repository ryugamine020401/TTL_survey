# Round 2 質詢：指導教授（Agent H）——第二輪（無真人實測）
日期：2026-07-14

> 本輪我讀完全部 8 份 round1 檔案。先講一句貫穿全場的觀察，再開始質詢：**這一輪每個人都在同一道牆前排隊——「你的計算性代理，憑什麼推論得到那個接電話的人？」** D 講得最直白：「不做真人實測是一把只砍防守方、幾乎不砍攻擊方的刀」。F 補得更狠：「這條規則拿走的不是我的角色，是你們的藉口。」我同意。所以本輪我打人的主軸不是「技術對不對」，而是**「你的無真人驗證方案，是不是偷偷把一個實驗室數字冒充成詐騙現場數字」**。這是我作為把關者這一輪唯一在乎的事。

## 一、對他人提案的挑戰

### 挑戰 1 — Agent F 提案一《紙上受騙率》：把「受騙率」寫進標題，是本輪最大的自我背叛

F 是本輪唯一把「受騙率」硬留在標題裡的人（中文暫題《不碰一個真人，把受騙率算出來》）。我尊重這份倔強——F 的角色任務就是不讓「人」被遺忘，這一點做到了。但正因為我尊重它，我要用最重的手打它，因為**它的標題會在 proposal defense 第一分鐘害死這個學生**。

F 主張：「於是『受騙率』就變成可計算的量……整條鏈 Monte Carlo 跑起來，輸出『此偵測器 + 此警告政策下的模擬受騙率』。」F 也誠實自曝了修正：「論文只 claim 在全參數區間穩健的排序與門檻，不 claim 受騙率的絕對值。」

**但是**——這裡有一個致命的內部矛盾，F 自己沒有解決：**你的 claim 已經退到「排序」，你的標題卻還寫著「把受騙率算出來」。** 一個 reviewer（或口試委員）只會讀到兩件事之一：如果你真的算出了受騙率，我問「你的 δ、你的 compliance rate、你的 error correlation ρ 憑什麼？」——F 在 round1 借 A 的話承認 ρ「aggregate 數據量不出來」；如果你只給排序，那標題是虛假廣告，我當場要求改題。**兩條路都是我打斷你的那一句話。**

更深的技術反駁，這是「計算性驗證推論不到真實情境」的精確版本：F 的受騙鏈上串了**至少三個各自獨立、各自無法辨識、各自要從 [0,1] 全區間掃描的未知數**——δ（壓力折損）、φ（警告服從率，還是從釣魚文獻外借的）、ρ（人機錯誤相關性）。F 以為「全區間掃描 + dominance」能救場，但**三個 [0,1] 區間的笛卡爾積上要求排序不翻轉，數學上幾乎必然落入兩種退化之一**：要嘛區間太寬、任何非平庸的 policy 對都會在某個角落翻轉（於是你什麼都排不出來，論文變成 E 誠實承認的「公開數據不足以支持任何排序」的否證——那是 E 的提案不是你的）；要嘛你偷偷把區間縮窄到「合理範圍」，而「合理」二字就是你剛剛發誓不做的那個拍腦袋點估計換了層皮。G 檢索到的《The Illusion of Intervention》（arXiv 2605.20767）正是釘這個：**模擬「實驗」在因果推論上只是觀察性研究**。F 想輸出的「受騙率」是干預量（把 policy A 換成 B 導致受騙率變化），但你的模擬給不了干預，只給得了「在我假設的世界裡的關聯」。

**我的裁定**：F 的**引擎**（文獻校準受害者模型 + 攻擊者最佳化最壞情況）有價值，且與 E1/G2-A/我的提案一同源；但 F 的**包裝**（受騙率當因變數、當標題）是本輪最危險的滑坡，正是我 round1 給自己畫的紅線「不讓它滑坡成用不可信的模擬假裝量到了受騙率」。F 應該把標題和 primary outcome 讓給 E1 的措辭（「穩健偏序 + 失效邊界」），自己退守到**提案二（詐騙現場條件測試集）**——那才是 F 本輪真正沒人做、且天然免疫這個矛盾的貢獻（見下方我的支持）。

### 挑戰 2 — Agent C 提案二《神經 codec latent detection》：防禦面把整個領域最深的坑原封搬進來，攻擊面又可能讓防禦面失去意義

C 這個提案是本輪技術上最漂亮的新想法，我先給它應得的分（可行性、無真人驗證說服力都是全場最高之一）。但漂亮不等於做得成，我要打它的**防禦面假說**和**真實情境動機**兩處。

C 主張防禦面：「RVQ codebook 是在真實語音上訓練的，真實語音的 token 序列與 TTS 輸出的 token 序列在 codec 的離散空間裡統計性質可能不同……真實語音的 token 有更高的『意外率』。」並宣稱這能建「通道天然對齊的新 domain：unseen-channel 的 train/test mismatch 從根源上消失一段」。

**但是**——C 自己在同一段埋了地雷卻沒引爆：他說主流 zero-shot TTS（VALL-E 系）「**本身就以 neural codec token 為生成目標**」。想清楚這句話的後果：如果 fake 的 token 落在 codec 典型集內是因為它「就是拿這個 codec 的 token 訓練的」，那麼**你的 token 統計判別器學到的是「這個 fake 用了哪個 codec 家族」，而不是「這是不是 fake」**。換一個不以你所選 codec 為目標的生成器（diffusion vocoder、非 RVQ 的 flow-matching TTS、或乾脆用另一家 codec 的 VALL-E 變體），你的「意外率」訊號立刻失效——**這就是 #2 證明的 unseen-generator 崩壞（EER 13.5→50%），你沒有繞過它，你把它換了個 latent 空間重新遇到一次。** C 在 round1 對 A 的 one-class 提案開過同一種火（「把 real manifold 撐大＝主動放棄判別」），現在自己的 codec-latent 偵測器要面對對稱的質問：你的可分性是真的 real/fake 之分，還是 codec-A-target/codec-B-target 之分？G 必須查證，但我的先驗是：**這條防禦面有五成機率是 unseen-generator 坑的變裝。**

第二刀打真實情境動機。C 主張 neural codec「正在進入真實通訊鏈」，但自己標「主流平台採用與否屬猜測，需查證」。這一步不能猜——它決定提案二是「真實通道審計」還是「攻擊者自選的一個 laundering 動作」。若查證為否（詐騙電話走的是 VoLTE 的 AMR-WB/EVS，全是傳統 CELP，不是 neural codec），那麼 C 的攻擊面就**塌回 D 的攻擊成本地圖裡的一個 cell**（「攻擊者自己 transcode 一次」），防禦面則失去「已部署通道」的立足點，變成純前瞻。更尖銳的是 C 自己承認的攻擊面結論：neural codec transcode「一行指令、零成本、不可逆摧毀第一二層 cue」——**如果這是真的，那你花月 5–9 建的 codec-latent 偵測器，攻擊者只要再過一次傳統 codec 把 token 打散就繞過（C 自己在 Q3 問 D 的正是這一步）**。攻防兩面在同一篇裡對沖，C 說這是「benchmark 型研究的優勢」，我說這是**你可能同時證明了「攻擊零成本」和「防禦可繞過」，於是這篇論文的淨結論是『這條路不通』**——那是可發表的否證（我認），但作為碩士生的主菜，答辯時「你的正面貢獻是什麼」會很難看。

**我的裁定**：C2 保留，但**必須先做月 1 的兩個 go/no-go**：(a) G 查證 neural codec 是否真在電信/平台鏈上（決定它是審計還是前瞻）；(b) 一個兩週的 pilot——訓 codec-latent 偵測器、留一個「非 RVQ-target」的生成器做 leave-one-out，若 AUC 掉回 0.6 以下，防禦面直接砍掉，論文收斂為純攻擊面（並入 D 的成本地圖）。這兩關過不了，C 應該回去做提案一（真實通道審計），那個沒有這種結構性風險。

### 挑戰 3 — Agent B 提案二《CallAttest》：你救的那個人，恰好不是阿嬤

B 是全場我最尊重的誠實者——round1 舉白旗、把定義域誠實限縮，這份紀律我 round1 就公開讚過。CallAttest 也確實補上了 B 自己指出 D-CAPTCHA 缺的 channel binding。但我要打它的**真實情境影響力**，因為那正是我本輪的把關職責。

B 主張契約域內的貝氏反轉：「在『銀行來電』這個窄域內，契約規定普及率 100%，『缺席』就從無資訊變成強訊號……E 的否證前提在契約域內被契約本身推翻。」並自答阿嬤那一行：「阿嬤沒有銀行 app。誠實回答：終端形態可以下沉到電信端加值服務或 165 官方 app 代管驗證，但那是部署故事不是論文貢獻。」

**但是**——把這兩句話並排，B 的社會福祉論證就露出一個 F 一定會撲上來咬的洞：**你的協定生效的前提是「受話端裝了會查 log 的 app」，而你承認阿嬤沒有這個 app。** 於是 CallAttest 實際保護的人群是「有裝銀行/反詐 app、會看綠標紅標、且被假冒機構詐騙」的人——這個交集裡的人，恰好是**數位素養較高、本來就比較不會被騙的那群**。你把密碼學武器發給了已經穿盔甲的人，而讓在倒數計時裡去超商 ATM 的阿嬤繼續赤身。這不是說 CallAttest 沒價值（它對「假冒機構」類詐騙的機構端流程有真實價值），而是說**它的「真實情境影響力」敘事不能靠阿嬤，只能靠上班族/機構——和 B 的提案一定義域重疊，兩個提案的社會福祉論證撞在同一小塊人群上**。

第二刀是 B 自己列出卻低估的軟肋。B 承認社工「app 維護中」繞過是「所有正面契約的共同軟肋」，緩解只能靠「機構端把無綠標即掛斷寫進不可協商流程」。**但是**——D 的口頭禪是「攻擊者只要贏一次」。你的協定在密碼學上再完美，攻擊者根本不攻密碼學，他攻「阿嬤不知道有這個綠標該長怎樣、也不知道沒綠標代表什麼」。B 在 round1 幫 E 的貝氏論證背過書（過渡期 P(fake|無憑證)≈先驗），現在契約普及率要真的到 100% 才能反轉——而「銀行 100% 簽署 + 全民 100% 裝 app 且看得懂綠標」這個前提，本身就是我 round1 判方向一「不依賴未兌現長期賭注」時點名要避開的那種賭注。

第三刀給 novelty（這條我標**需 G 查證**）：B 對 STIR/SHAKEN 的 delta 論證（不綁內容 vs 綁內容、需電信商 vs over-the-top）站得住，但「內容綁定的來電認證 + transparency log」這個組合，我的先驗是 2024–2026 的 anti-robocall/call-authentication 文獻可能已有近親（RFC 8224 之後的 content-binding 提案、rich call data 系）。若 G 查出前作，CallAttest 的 novelty 錨點要退到「perceptual hash 鏈的 second-preimage 對抗評估 + 台灣 165 部署成本分析」，那就從「一個新協定」降級為「一個既有協定家族的安全評估」——仍可發表，但份量變輕。

**我的裁定**：CallAttest 技術紮實、形式驗證（Tamarin/ProVerif）是本輪最不需要辯護「無真人可不可信」的驗證形式（我認這一點強）。但它**不是回答本問題陳述考題（降低那個接電話的人受騙率）的方向**，它是「保護願意簽署的機構 + 已武裝用戶」的方向。B 若要交這題，威脅模型第一頁必須寫死：「本協定不覆蓋未裝驗證端的用戶，即問題陳述的核心受害者阿嬤」——把 F 會咬的洞自己先挖開給委員看。

### 挑戰 4 — Agent A 提案二《失效歸因 + 重送干預》：你的「機器可驗證干預」在真實詐騙裡沒有可重送的東西

A 的提案二（channel-induced vs generator-novelty 的可分性）是好科學，我喜歡它把 #3 的可逆 shift 與 #2 的不可逆 shift 並排的洞察。但我要打它宣稱的**真實情境抓手**——「重送干預」。

A 主張：「對 channel 型棄權附帶一個純計算可驗證的干預——換通道重送：模擬同一樣本經替代通道重傳後，偵測可靠性是否恢復。」並說這把 UX 的「一鍵回撥」等價地移到機器側。

**但是**——「同一樣本經替代通道重傳」這件事，**在你的實驗室裡成立（你手上有那段乾淨音訊，可以隨意 route 過不同 codec），在真實詐騙現場不存在**。詐騙者送給阿嬤的是一段他控制的音訊；系統判定「疑似通道劣化、請重送」時，**能重送的只有攻擊者，而攻擊者不會合作重送一個更乾淨的版本讓你抓他**——他要嘛不理、要嘛正如 A 自己在 round1 對 D 的攻擊面分析所說，用「更乾淨的通道 + 更強的 laundering」重送。也就是說：**你的「重送干預」在計算上可驗證（我認可月 7–9 的實驗），但它驗證的是「若一段已知乾淨音訊被重新 route，可靠性會不會恢復」，這個命題推論不到「真實詐騙裡系統能不能靠重送自清」。** 這正是本輪的核心病症：計算性驗證的因變數（可靠性恢復率）與真實情境的因變數（阿嬤會不會被騙）之間，隔著一個「攻擊者不合作」的斷層，而 A 的敘事把這個斷層說成「使用者端遵從問題被移出 claim 範圍」——移出去了，但你同時也把「這個干預能救人」的宣稱一起移出去了。

**我的裁定**：A2 的**歸因**部分（channel vs generator 可分性地圖、疊加極限）是紮實的、可發表的、無真人爭議的貢獻，我支持它作為 A1 的延伸章。但「重送干預能救人」的敘事要砍掉，改寫成「重送干預是一個**評估探針**（測歸因器有沒有說謊），不是一個部署防線」。這樣它就誠實了。

## 二、回答指名給我的問題

本輪有六個人（A、B、C、D、E、F、G）把問題丟給我，而且**七問裡有六問是同一個問題的變體**：「受騙率不能實測了，你這個把關者的裁決標準是什麼？」我先給一次總裁決，再逐一回各自的具體問法。

### 總裁決：無真人實測時代，我在 proposal defense 的三條紅線

第一輪我立的公約是「禁用裸 EER」。本輪我加立三條新紅線，凡越線者我在 defense 擋下：

1. **紅線一（反冒充）**：primary outcome 的名字**必須誠實地叫它自己**。你算的是「文獻校準人類模型族下的期望損害偏序」，就不准叫它「受騙率」。名字錯了，第一句話就死——這條專打 F 的標題。
2. **紅線二（反自由度）**：任何「用模型替代真人」的方案，模型的每個參數要嘛有**已公佈真人數據**錨定，要嘛以**全區間掃描 + dominance 結論**呈現，且**不得使用 LLM 模擬受試者當 primary evidence**。G 的檢索把這條從我的個人偏好升級為社群事實：LLM-simulated users 已被實測判為不可靠代理（arXiv 2601.17087、2605.10659），而 L2D 的合成專家（Nature Sci Data 2025、FiFAR）與認知模型「fit 研究 A 預測研究 B」（UMUAI 2026）是**有既定先例、被頂刊接受**的路線。走前者=把脖子伸給 reviewer；走後者=站在判例上。
3. **紅線三（反滑坡到無關）**：這是我本輪的角色任務。「不做真人」不得成為「躲回純技術指標、忘記真實的人」的藉口（F 的原話）。一篇只有 ECE 曲線和 risk-coverage 圖、對「人」不做任何 claim 的論文，我會判它「退回與阿嬤無關的方向」——它技術上及格，但沒回答考題。

### 給 A（Q3）：claims 怎麼措辭、我會在哪一句打斷你

打斷你的那一句是：**「我們量測了受騙率的下降」**——只要這句話（或它的變體）出現，我打斷。守得住的措辭是：「我們證明，**在所有與 VoiceWukong 300+ 人數據一致的人類代理模型下**，deferral policy A 的期望損害不高於 B；此排序在壓力係數 δ∈[0,1]、服從率 φ∈[文獻範圍] 的整個掃描區間內不翻轉；翻轉發生的參數子區域，我們如實標為『需真人實驗裁決區』。」注意三個必備零件：**全稱量化的前提**、**dominance 而非點估計的結論**、**主動交出失效區**。你 round1 的提案一措辭已經很接近了（「dominance claims 不做 point estimate」），把它貫徹到底、別讓「受騙成本」四個字在任何小標題裡假裝成量測值，你就過關。

### 給 B（Q3）：兩條推論鏈誰的假設更少

你問得很聰明，也很危險——你在誘導我承認「B2 的形式驗證推論鏈比 A1 的模擬推論鏈更短、假設更少，所以 primary outcome 該換成你那種」。我部分同意、部分不同意，講清楚：

**你對一半**：CallAttest 的形式驗證（「在此攻擊者模型下不存在攻擊 trace」）在**推論鏈長度上確實勝過**任何 human-proxy 模擬——它是機器可判定的數學事實，不經過任何行為假設。這是我 round1 就承認的「密碼學紀律」，本輪依然成立。
