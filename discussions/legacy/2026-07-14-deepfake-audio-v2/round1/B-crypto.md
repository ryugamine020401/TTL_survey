# Round 1 提案：密碼學/Provenance 研究者（Agent B）——第二輪（無真人實測）
日期：2026-07-14

> 撰寫前提：已完整重讀 00-problem-statement、survey/README（#1–#8）、legacy 03-synthesis.md。我在第一輪是全場立場移動最大的角色——Round 3 舉白旗承認「provenance 對阿嬤的即時詐騙電話救不了」，把定義域限縮到非即時媒介，soft binding 改為「索引不 payload」構造。本輪我站在那個白旗之上發言，不撤回任何已承認的失敗。

---

## 一、新限制對我的視角意味著什麼

先講一個整體觀察：**「不做真人實測」這條限制，對全場五個方向的殺傷力分佈極不均勻，而它對密碼學路線幾乎是零殺傷、甚至是利多。** 密碼學的驗證傳統本來就是計算性的——security game、formal verification、資訊理論界限、原型量測。我們這一行從來不問受試者「你覺得這個簽章可信嗎」，我們問「攻擊者在多項式時間內偽造它的機率是多少」。所以這條限制對我而言，不是失去工具，而是全場其他人被拉到我熟悉的戰場上。

逐一盤點五個方向：

### 方向一（誠實棄權 + 警告 UX + 受騙率量測）——核心驗證被抽掉一半
這是受創最重的方向，而且傷在心臟。第一輪 H 給它首選的理由是「全場唯一能指著數據說『這個設計讓受騙率從 X 降到 Y』的題目」——那個數據來自 30–50 人的 user study。現在 user study 被禁，**primary outcome（受騙率）失去了直接量測手段**。存活的部分：shift-aware calibration benchmark、六種棄權機制比較、D 的 `max P(confident-real|fake)` 對抗評估軸——這些全是計算性的，而且月 1–4 的保底半篇 benchmark 本來就設計成「不依賴 IRB」。可以用 VoiceWukong（#2）已公佈的 300+ 人數據建 human proxy model 做 deferral policy 模擬（問題陳述明文允許），但要誠實：**「警告設計 → 行為改變」這一環無法從 aggregate FAR 數據建模**——#2 的人類數據告訴你人類在無警告下對高品質 deepfake FAR >82%，但沒有告訴你「看到警示後 FAR 降多少」。這一環要嘛引用 usable-security 文獻的既有效應量（外推，信度打折），要嘛從 claims 裡誠實刪掉。方向一不會死，但它的題目必須改名——「受騙率實證」四個字不能再放在標題裡。

### 方向二（真實通道存活 benchmark）——幾乎不受影響，僅語料來源需微調
rig 本身是設備對設備的物理量測，不涉及人類受試。唯一要動的是語料規劃中「團隊錄音（簽知情同意）」那一項——雖然錄自己人嚴格說可能不算 human subjects research，但問題陳述說「不做任何需要 IRB 的事」，最乾淨的做法是**全部改用公開資料集的 bona fide 語料**（ASVspoof、LibriSpeech、公開的繁中語料）播放過通道。法律路徑（通保法 §29，G 的 T2 查證）不變。這個方向在新限制下反而更輕：時程表的「月 0 IRB 送件」直接刪除。

### 方向三（攻擊成本地圖）——完全不受影響
本來就是純計算的紅隊評估：現成生成器 + 現成 laundering 工具 + 現成偵測器 checkpoint + beam search。第一輪的規劃裡沒有任何真人成分。C 的物理可逆性標註是資訊理論事實，更不需要人。

### 方向四（Active Liveness Probing）——中度受創，語料建構需重設計
它的 RQ1–RQ3 是機器攻防量測，主體不需真人。但第一輪實驗規劃裡有兩處埋了真人：「非同步挑戰-回應語料」的**真人錄回應**組、「切換點語料」的**真人共犯接手段**。替代路徑存在：非典型發聲用公開語料（whispered speech 有 wTIMIT、笑聲/非語言發聲有 VocalSound 類語料、情緒語音有 CREMA-D 等——具體可用性需 G 查證，此處標為**待驗證的猜測**）；切換點語料可以用公開語料的不同語者段拼接模擬共犯接手。可行，但「真人在壓力下執行挑戰的表現分佈」這個 bona fide 端的自然變異就只能用公開語料的分佈近似，FRR 估計的外部效度會被 reviewer 攻擊。受創但可搶救。

### 方向五（Provenance 可達性地圖）——我的主場，幾乎零影響
全部驗證手段本來就是計算性的：bit-level I(embedded;recovered) 量測、端到端 demo、security game、#6 的 formal methods 傳統、政策審計。第一輪時程表的「月 0 IRB」本來就只是為了跟方向二共用語料，現在跟著方向二一起改用公開語料即可。**新限制下，方向五是五個方向中唯一一個「原規劃一個字都不用改主張、只改語料來源」的方向。**

小結：新限制重新洗了牌。第一輪的推薦排序隱含一個權重——「能直接量受騙率的方向最高分」。這個權重的量測手段現在被拔掉了，所有方向都只能用計算性代理去逼近「受騙率」。這不表示方向五自動升到首位（它「救不了阿嬤」的白旗還插在那裡），但表示**全場的比較基準回到了同一條起跑線：誰的計算性代理與「真實受騙率下降」之間的推論鏈最短、假設最少，誰就該贏。**

## 二、思辨過程（自我質疑的獨白）

我給自己立三條紀律，然後過一遍候選想法：
（甲）不得原樣重提已擊沉提案——Integrity Clash 作為主軸、通道一致性、人群連結都不碰；
（乙）我 Round 3 舉的白旗不撤回——不假裝 provenance 能救即時詐騙電話的一般情境；
（丙）每個候選都要先過 D 的問題（最便宜繞過是什麼）和 F 的問題（阿嬤那一行到底算什麼）。

### 候選一：C2PA audio profile 的純 formal-methods 安全分析（#6 的音訊續集）

想法：UMBC（#6）用 formal methods 證了 C2PA 五項安全目標全數未達成，但他們的分析以影像為主；audio 的嵌入方式（BMFF vs WAV/MP3 chunk）、exclusion range 語意、soft binding 缺位都有 audio 特有的攻擊面。做一份「C2PA v2.4 audio 的五目標形式化分析 + 攻擊實證」。

自我質疑：
1. **scoop 風險是紅色的。** 第一輪 Integrity Clash 五人撞題、#7 原作者已預告後續，UMBC 團隊也持續在更新分析。一個碩士生跟兩個活躍團隊搶同一條純分析賽道，勝算低。
2. **對受騙率的推論鏈太長。** 就算我證明了 audio manifest 的 exclusion range 可竄改，這服務的是標準制定者和查核組織，H 第一輪已判「服務查核生態而非阿嬤，不是本問題陳述的推薦主軸」。新限制沒有改變這個判定。
3. 純規格分析的工作量對碩論而言可能反而「太薄」——#6 是一整個實驗室的產出。

**處置：淘汰作為主軸。** 但它的方法論（五目標對照、formal 化安全宣稱）降級為候選五的一個評估模組——這與我 Round 3「Integrity Clash 降為模組」的處置一致。

### 候選二：Validator / Decoder Differential Testing（差分測試找矛盾判定）

想法：#6 有一個被低估的實證——同一張圖，Adobe Inspect 判有效、Verifieddit 判無效（Nikon 憑證撤銷案例）。「生態系內驗證器彼此矛盾」本身是攻擊面：詐騙者只需要把受害者導向判定寬鬆的那個 validator。把這件事系統化：自動生成邊界 manifest / 劣化音訊，對 C2PA validators 與 watermark decoders（AudioSeal、SynthID）做差分測試，量測「判定分歧率」作為生態系級安全指標。完全計算性，工具化，像 fuzzing。

自我質疑：
1. **audio 的 C2PA validator 生態太小。** 影像端有 Adobe/Verifieddit/Truepic 多個實作可差分；audio 端目前接近只有 c2patool/c2pa-rs 一脈（此為**猜測**，需 G 查證 2026 年中的實作清單）。差分測試需要至少兩個獨立實作才有「分歧」可言，樣本可能不足以撐起一篇論文。
2. watermark decoder 端的分歧（同一段劣化音訊，AudioSeal 說有標、SynthID 說沒標）嚴格說不是 bug，是各家 watermark 本來就不互通——分歧率會高到沒有資訊量。
3. 但有一個窄化版是有價值的：**同一個 decoder 在通道劣化梯度上的判定翻轉行為**（在哪個劣化深度從「有標」翻成「無標」、翻轉是否單調）——這直接關係 Article 50 的可執行性。

**處置：淘汰作為獨立題目，窄化版併入候選五的實驗軸（三）。**

### 候選三：幫方向一補洞——用 VoiceWukong 人類數據建 computational deception model

想法：既然方向一的 user study 被禁，那就把 #2 的 300+ 人數據（人類對各品質層級 deepfake 的 FAR 分佈）建成 parametric human model，接上偵測器的 risk-coverage 曲線，模擬「偵測器 + 警告 + 人」的 pipeline expected deception rate。

自我質疑：
1. **這不是我的主場，而且最弱的一環恰好在我幫不上忙的地方。** #2 的數據是「無警告、無情境壓力下的判別 FAR」，方向一真正要量的是「警告介入後、壓力情境下的行為改變」。從前者外推後者，中間隔著整個 usable security 文獻——這個外推的辯護該由 A/H/F 來做，我做會做成半吊子。
2. 我能貢獻的部分（confident-real 攻擊面的形式化、「警告訊號本身能否被攻擊者偽造/抑制」的分析）本來就已經被方向一收編了，不需要我另立題目。
3. 但這個候選讓我看清一件事：**新限制下，「模擬人類」的可信度會成為全場攻防焦點**。我要在留給其他人的問題裡逼 A 和 H 正面回答這個外推的辯護策略。

**處置：淘汰（讓賢），轉化為給 A/H 的質詢問題。**

### 候選四：CallAttest——機構端來電在場證明協定（out-of-band、內容綁定、透明日誌）

想法的起點是回顧我 Round 3 被 C 判的死刑：「電話通道可靠 payload 逼近 0 bit，一個 hash 要 128 bit 塞不進去」。我當時的迴避是「索引不 payload」——波形內只塞 20-bit 索引。但還有一條我當時沒走完的路：**乾脆 0 bit——完全不用語音通道承載任何密碼學材料，全部走 out-of-band 資料通道。**

構造草圖：高風險機構（銀行、165、政府機關）發起通話時，同步在 transparency log 上發布一筆簽署的 call commitment（時間窗、宣稱的被叫號碼雜湊、以及**通話音訊的滑動窗 perceptual hash 鏈**——這是我 Round 3 的時序鏈式綁定，從 in-band watermark 搬到 out-of-band）。受話端的 app（銀行 app 或 165 反詐 app）收到「宣稱來自本行」的來電時查 log：有匹配的 commitment 且 hash 鏈對得上 → 綠標；查無 → 紅標。驗證是**機器對機器的二元判定**，人類決策被移出關鍵路徑。

為什麼這不違反我的白旗：白旗說的是「provenance 對**無憑證的**即時詐騙電話零覆蓋、缺席訊號的貝氏資訊增益趨近零（E 的論證）」。但 F 在第一輪已經給出破解：**局部正面契約**——在「銀行來電」這個窄域內，契約規定普及率 100%，「缺席」就從無資訊變成強訊號。E 的貝氏否證在契約域內不成立，因為 P(有憑證|真的是銀行) 被契約推到 1。第一輪 B 與 F 獨立收斂到這個同構設計，被 03-synthesis 記為「通過可用性檢驗的最強訊號」。我現在做的是把這個契約**從應用故事升級為可形式化驗證的密碼學協定**。

自我質疑：
1. **STIR/SHAKEN 前作問題。** 電信業已有 caller ID attestation 標準（RFC 8224/8588，北美已部署）。我的 delta 必須說清楚：(a) STIR/SHAKEN 認證的是「主叫號碼沒被 spoof」，不綁定**內容**——SIM swap、企業話務系統被入侵、或合法號碼轉租後，攻擊者拿著「真號碼」打詐騙電話，STIR/SHAKEN 全綠燈；我的 hash 鏈綁定的是「這一段音訊確實是該機構這一通通話發出的」，把 mid-call injection 和事後移花接木也擋掉。(b) STIR/SHAKEN 需要電信商全鏈路配合，跨國/跨網即斷（台灣未部署）；out-of-band 構造是 over-the-top 的，機構自己就能單邊部署，不求電信商。這個 delta 站得住，但相關工作一節必須正面處理，否則 reviewer 第一刀就是「這不就是 SHAKEN 加推播」。
2. **D 會問的最便宜繞過**：我自己先列——(i) 社工繞過：「本行 app 今日維護中，沒有綠標是正常的」→ 這是所有正面契約的共同軟肋，緩解只能靠機構端把「無綠標即掛斷」寫進不可協商的流程設計，且我誠實承認協定不防這條，這一環在論文威脅模型第一頁；(ii) perceptual hash 的 second-preimage：攻擊者找一段語意不同但 hash 落在容忍半徑內的音訊——這是真正的密碼學攻擊面，perceptual hash 不是 cryptographic hash，其對抗強健性是本題最大的技術風險，必須做 adversarial 評估（這也是我要丟給 D 的問題）；(iii) relay：把真銀行通話轉接給受害者、攻擊者中途插話？hash 鏈的滑動窗設計正是為了讓插入段斷鏈——但即時 relay 下的時間窗容忍度要實測。
3. **F 會問的阿嬤那一行**：阿嬤沒有銀行 app。誠實回答：終端形態可以下沉到電信端加值服務或 165 官方 app 代管驗證，但那是部署故事不是論文貢獻；論文貢獻止於「協定 + 證明 + 原型 + 成本分析」。覆蓋域是「假冒機構」類詐騙——這在台灣詐騙類型中佔比高（**猜測**，需引 165/刑事局公開統計確認具體佔比），但不覆蓋假冒親人。範圍窄而誠實，比範圍大而虛胖好——這是我從第一輪學到的最重要一課。
4. **會不會太「協定設計」而缺實驗量？** 不會：Tamarin/ProVerif 形式化驗證 + 原型延遲量測 + perceptual hash 對抗評估 + relay 時間窗攻防，四個實驗單元都是計算性的，一年排得滿也排得完。

**處置：存活，成為正式提案二。**

### 候選五：Provenance 可達性地圖的無真人收斂版（方向五改造）

第一輪方向五有三個構造創新（索引式 soft binding、時序鏈式 hash 綁定、層間依賴證據圖）加政策審計軸。新限制下它幾乎不用改，但我要自我質疑的是別的：

1. **它會不會太散？** 第一輪的方向五是我 Round 3 大撤退後把殘餘部隊全編進一個框架的產物——量測、構造、稽核、政策四個軸。碩論一年做四個軸，每個都淺。候選四已經把「時序鏈式綁定」搬走做大做深了，那方向五剩下的核心應該收斂到：**「索引式 soft binding 構造 + 通道存活量測 + Article 50 審計」**這條單線——構造是主菜，量測是構造的容量依據，審計是量測的政策出口。層間依賴證據圖降為選配模組（它繼承自被擊沉的 Integrity Clash，繼續縮編是正確方向）。
2. **與方向二的分工重疊。** 第一輪已議定：方向二＝量測/benchmark，方向五＝構造/政策/稽核。若本輪方向二沒人做，我的通道矩陣就得自建——退路是先用 #3 的模擬 codec 矩陣（AMR-WB/EVS/Opus + PLR，完全計算性、零工程風險）跑完構造驗證，真實 rig 作為 stretch。模擬矩陣對「構造在低容量通道能否工作」這個問題是保守估計的反面——模擬通常比真實樂觀（Deepfake-Eval-2024 的 48% AUC 落差先驗），所以我要把「模擬樂觀偏差」明寫進限制一節，容量預算取模擬值再打安全折扣。
3. **20-bit 索引的假設還成立嗎？** 我 Round 3 的構造假設電話通道有 ~20 bit 可靠容量。這個數字是從 C 的判決反推的猜測，沒有實測依據。如果 neural codec（新一代通訊 codec 或平台端 neural compression）把可靠容量壓到 5 bit 以下，索引式構造也死。所以量測軸不是配菜，是構造的生死判官——這也是我要丟給 C 的問題。
4. 政策時效是利多：Article 50 於 2026-08-02 生效，第一份 machine-readable 標記的通道可讀性審計至今無前作（第一輪 G 查證），這個空白窗口正在倒數。

**處置：收斂後存活，成為正式提案一。**

### 淘汰與存活總覽

| 候選 | 處置 | 一句話理由 |
|---|---|---|
| 一：C2PA audio 純 formal 分析 | 淘汰→模組 | scoop 紅色 + 推論鏈太長，服務查核生態非民眾 |
| 二：Validator 差分測試 | 淘汰→窄化併入提案一 | audio validator 生態太小，撐不起獨立題目 |
| 三：computational deception model | 讓賢→轉為質詢 | 不是我的主場，最弱環節我幫不上忙 |
| 四：CallAttest 協定 | **正式提案二** | 局部正面契約的密碼學實現，0-bit in-band 破容量死結 |
| 五：方向五收斂版 | **正式提案一** | 新限制下唯一零改動方向的再收斂，政策窗口倒數中 |

兩個提案的共同敘事：**C 判了電話通道 in-band 容量的死刑之後，provenance 還剩兩條活路——「塞一個最小索引進波形」（提案一，服務非即時媒介的轉傳鏈）與「一個 bit 都不塞、全走帶外」（提案二，服務即時的機構契約域）。兩題合起來就是 provenance 在真實通訊世界的完整可達性地圖。**

## 三、正式提案

### 提案一：《索引不 Payload——低容量通道下的音訊 Soft Binding 構造、多層訊號存活量測與 EU AI Act Article 50 可讀性審計》
*Index, Not Payload: An Audio Soft-Binding Construction for Low-Capacity Channels, with Multi-Layer Signal Survival Measurement and an EU AI Act Article 50 Readability Audit*

**核心 idea**：C2PA 規格（#4）明載 soft binding 是 manifest 在 metadata 被剝除後的復原機制，但沒有給出 audio 構造；而真實通訊通道的 watermark 可靠容量遠低於一個 cryptographic hash（128+ bit）的需求。本構造讓波形內只承載 k-bit transparency-log 索引 + ECC（k≈20 即可索引 2^20 筆完整 manifest），把「內容與 manifest 的綁定」從 payload 問題轉為查表問題；並以滑動窗 perceptual hash 鏈（存於 log 端、不佔 in-band 容量）抵抗局部剪接移植攻擊。量測軸系統性掃描 codec × PLR 梯度下的可靠容量與各層訊號（manifest 容器、傳統 watermark、latent watermark）的存活邊界，回答「構造的 k 預算到底有多少」與「Article 50 要求的 machine-readable 標記在詐騙實際流通的通道上可不可讀」。

**為什麼有機會成立**：
- Gap 直接對應 survey 地圖第 2、3 點：#4 的 soft binding 缺 audio 構造；#7 證明 watermark 與 manifest 不互綁就會被去同步（Integrity Clash）；#6 的五大缺陷提供安全目標框架。
- 容量死結是真實的（C 第一輪判決），而索引式構造是目前唯一已提出的迴避路線（第一輪 03-synthesis 已記錄，本輪做深）。
- Article 50 於 2026-08-02 生效，可讀性審計無前作（G 第一輪 R5/T3 查證），政策發表窗口明確。
- 誠實邊界繼承自我的白旗：定義域是**非即時媒介**——LINE 語音訊息、轉傳的媒體檔案、權威來源發布的錄音——不宣稱覆蓋即時詐騙電話。F 第一輪判定表中「上班族（LINE 語音訊息）」與「選民」兩個人物在此域內。

**技術路線**：
1. 月 1–3：模擬通道矩陣（#3 的 6 codec × 5 PLR，加社群平台轉檔管線）上量測 AudioSeal / SynthID / latent-space watermark 的 bit-level I(embedded;recovered)，加 C2PA manifest 容器存活（c2patool 簽署 → 各通道 → 驗證）；產出「容量-通道地圖」＝構造的 k 預算依據 ＝ **保底可發表單元**。
2. 月 4–6：依實測容量設計索引編碼（ECC 選型、錯誤率-索引空間 trade-off）、transparency log 原型（既有 CT-style log 改造）、滑動窗 perceptual hash 鏈的粒度設計。
3. 月 7–9：端到端 demo（簽署 → 平台轉檔/通道劣化 → 無 metadata 復原 manifest 並驗證）；對 D 第一輪攻擊清單做安全評估：strip-to-evade、mark-to-frame、選擇性存活、局部剪接移植、log 投毒（大量註冊垃圾 manifest 稀釋索引空間——本輪新增的攻擊面）。
4. 月 10–12：Article 50 審計軸（法規要求 vs 實測可讀邊界的對照表）、#6 五目標對照的 formal 化論證（候選一殘值）、decoder 判定翻轉行為分析（候選二殘值）、寫作。

**計算性驗證方案（替代真人實測的部分與可信性論證）**：
- 原方向五的真人成分只有語料自錄一項 → 全部改用公開資料集 bona fide（ASVspoof、LibriSpeech、公開繁中語料）；通道以 #3 的模擬工具鏈為主，真實 rig（設備對設備、播放公開語料、不涉人類受試）為 stretch。
- 「聽起來自然嗎」的品質判斷 → PESQ/ViSQOL 等客觀指標 + 引用 watermark 原論文已公佈的 MOS 數據，不自辦聽測。
- 「合法片段轉發的誤警率」原本隱含使用者行為 → 改為程式化模擬轉發管線（裁剪長度、re-encode 次數的參數掃描），分佈假設明標並做敏感度分析。
- **為什麼結論仍可信**：本提案的所有 claims 本質上是資訊理論與密碼學性質——bit 存活率、綁定的安全性、驗證的可判定性。這些性質的成立與否從來不取決於人類感受；人類環節（「使用者看到驗證結果會不會信」）誠實地排除在 claims 之外，寫進 limitations。這正是密碼學的紀律：精確陳述我證明了什麼、沒證明什麼。

**預期貢獻**：(a) 第一個面向低容量通道的 audio soft binding 具體構造 + 開源實作；(b) 第一份多層 provenance 訊號在通訊通道上的系統性存活地圖；(c) 第一份 Article 50 machine-readable 標記的可讀性審計——若結論是「電話級通道全滅」，即是對政策路線的重要否證，負面結果照樣有政策級發表價值；(d) C2PA audio profile 的修補建議（回饋標準組織）。

### 提案二：《CallAttest——來電在場證明：機構通話的帶外內容綁定認證協定與形式化驗證》
*CallAttest: Out-of-Band, Content-Bound Attestation for Institutional Phone Calls, Formally Verified*

**核心 idea**：接受「無憑證的即時詐騙電話 provenance 零覆蓋」（我的白旗）與「缺席訊號在開放世界資訊增益趨近零」（E 的貝氏否證），但在 **F 的局部正面契約域**內反轉這兩個否證：高風險機構（銀行、165、政府）承諾其所有外撥通話必在 transparency log 發布簽署的 call commitment（時間窗、被叫號碼雜湊、通話音訊的滑動窗 perceptual hash 鏈），受話端 app 做機器對機器的二元驗證——契約域內「查無 commitment」即紅標。語音通道 in-band 承載 0 bit，徹底繞開容量死結；hash 鏈綁定內容，使協定同時抵抗號碼冒用、mid-call injection 與事後音訊移花接木——這是 STIR/SHAKEN（只認證主叫號碼、需電信商全鏈路配合、不綁內容）給不了的三件事。

**為什麼有機會成立**：
- 契約域內的貝氏反轉有第一輪的雙重背書：B 與 F 兩個角色獨立收斂到局部正面契約設計，03-synthesis 記為「通過可用性檢驗的最強訊號」；E 的否證前提（低普及先驗）在契約域內被契約本身推翻。
- 假冒機構是語音詐騙的主要類型之一（165 公開統計可查——具體佔比為**待查證**，列為月 1 文獻工作），攔截面真實存在；且驗證主體是機器/機構端流程，阿嬤零操作的部署形態在第一輪方向四已被 F 認可為封死社工繞過的正解。
- 密碼學上站在成熟地基上：transparency log（CT 的十年實踐）、channel binding（我第一輪指出 D-CAPTCHA 缺的正是這個，現在自己補上）、formal verification 工具鏈（Tamarin/ProVerif）皆現成。#6 已示範 formal methods 在 provenance 領域的發表模式。
- Over-the-top 單邊部署：不需電信商配合、不需 LINE 整合，機構自己的 app 就是驗證入口——不踩第一輪 H 的平台紅線。

**技術路線**：
1. 月 1–2：威脅模型形式化（攻擊者能力：號碼 spoofing、SIM swap、話務系統入侵、relay、社工）；相關工作正面清算（STIR/SHAKEN、RFC 8224/8588、既有 OOB 認證方案）。
2. 月 3–5：協定設計 v1 + Tamarin/ProVerif 符號化驗證（authentication、replay resistance、commitment 不可否認、時間窗安全）；迭代到證明通過。
3. 月 6–8：原型實作（log + 簽署端 + 驗證端）與端到端延遲量測（commitment 發布到可驗證的延遲必須小於「受害者開始信任來電」的時間窗——後者引用文獻的通話行為統計，不自測）；滑動窗 perceptual hash 在真實 codec 劣化下的匹配容忍度掃描（借提案一的通道矩陣）。
4. 月 9–11：對抗評估三軸——(i) perceptual hash 的 adversarial second-preimage 搜尋（給定容忍半徑，攻擊者最佳化找語意惡意但 hash 匹配的音訊，量攻擊成本，接 D 的 attacker-cost 框架）；(ii) relay/插話攻擊的時間窗攻防（插入段造成的斷鏈檢出率 vs 窗長）；(iii) log 端攻擊（搶先註冊、投毒、split-view——CT 文獻的已知攻擊移植過來檢查）。
5. 月 12：coverage × base-rate 期望成本分析與寫作。

**計算性驗證方案（替代真人實測的部分與可信性論證）**：
- 協定安全性 → **符號化形式驗證**（Tamarin/ProVerif），這是比 user study 更強的保證形式：不是「50 個受試者沒被騙」，而是「在此攻擊者模型下不存在攻擊 trace」。
- 「降低受騙率」的量測 → 不做真人，改為三段式計算性代理：(a) 形式驗證證明「契約域內假冒機構的來電必然觸發紅標」（機器可判事實，不涉人類判斷）；(b) attacker-cost 分析量化攻擊者被迫遷移的成本（放棄假冒機構、轉向不受保護的詐騙類型的成本差）；(c) 用 165/刑事局**已公佈**的詐騙類型分佈做 coverage × base-rate 期望損失模型（引用公開數據，問題陳述明文允許）。
- 通話音訊素材 → 全部使用公開資料集語料過 codec 管線，無任何自錄或人類受試。
- **為什麼結論仍可信**：本協定刻意把人類決策移出關鍵路徑——驗證是 app 對 log 的機器查詢，紅標/綠標是二元可判定事實。論文 claims 止於「協定在形式模型下安全 + 原型延遲可部署 + 攻擊成本被抬升 X」；「使用者看到紅標會不會掛電話」這最後一環誠實列為 out of scope，並指出機構端強制流程（紅標即由機構端擋下交易，而非期待使用者自行掛斷）是把這一環也技術化的部署路徑。推論鏈上每個假設都明標且可獨立檢驗——這比一個 30 人 user study 的外部效度更經得起攻擊。
- 誠實邊界（威脅模型第一頁）：不覆蓋假冒親人詐騙；社工「app 維護中」話術是所有正面契約的共同殘留軟肋；perceptual hash 非 cryptographic hash，其對抗強健性是本題最大技術風險（失敗備案：hash 鏈降級為粗粒度時間戳綁定，協定仍擋號碼冒用與事後移花接木，內容綁定粒度誠實下修）。

**預期貢獻**：(a) 第一個內容綁定、over-the-top、可單邊部署的機構通話認證協定（對照 STIR/SHAKEN 的三項結構性差異）；(b) 協定的機器可檢查形式化驗證產物（Tamarin 模型開源）；(c) perceptual hash 對抗強健性在認證場景的首份系統性評估；(d) 給金融監理與 165 的部署成本-覆蓋分析。它是全場「即時詐騙電話」這個最難情境中，provenance 一側唯一不與我的白旗矛盾的進攻路線——不是偵測 deepfake，而是讓真話可以自證，讓契約域內的假話因缺席而現形。
