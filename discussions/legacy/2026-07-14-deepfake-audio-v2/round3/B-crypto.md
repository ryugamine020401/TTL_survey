# Round 3 答辯：密碼學/Provenance 研究者（Agent B）——第二輪（無真人實測）

> 我在 Round 1（本輪）站在自己 legacy 舉的白旗上發言，Round 2 用「精確陳述我證明了什麼、沒證明什麼」這條紀律拆了 D、A、C 三人的推論鏈。Round 3 輪到我把同一條紀律用在自己身上——而結果是殘酷的：**我的提案二 CallAttest 被全場七個角色從七個不同方向擊沉，而且其中一顆（G 的 AuthentiCall 魚雷）是致命傷。** 我不打模糊仗，也不硬撐。這份文件的主軸是：接受絕大多數對我的挑戰，把 CallAttest 作為「新協定」的宣稱正式撤回，把它殘餘的**唯一誠實貢獻**（D 與 F 各自獨立指出的那個）重構出來；把提案一收斂進全場公認最硬的地基（真實通道存活審計群）；並把我這一行能給的兩件不會做成半吊子的東西（Article 50 審計 + 無綠燈形式不變量）交出去。

## 一、逐條答辯

我先把 Round 2 中所有指向我兩個提案的挑戰列出來，逐一標「接受並修正」或「反駁」。我數了一下：**提案二收到 7 條攻擊（G/C/A/E/D/F/H 各一），提案一收到 2 條（C 的容量 go/no-go、D 的攻擊成本評級）。** 攻擊密度本身就是訊號——我如實面對。

### （提案二 CallAttest）挑戰 G-2：AuthentiCall（USENIX Security 2017）已經做完了你宣稱的全部 delta

**G 的原話**：AuthentiCall（Reaves, Blue, Abdullah, Vargas, Traynor, Shrimpton, USENIX Security 2017）做了「cryptographically authenticate **both identity and content** of phone calls、用**形式化驗證過的協定**把低位元率資料通道綁到異質音訊通道上、偵測 99% 被竄改通話音訊、OTT 單邊部署繞開 SS7」。G 逐條對照我的 delta 表，四項全中，裁定「CallAttest 若不在第一頁把 AuthentiCall 列為頭號前作並清楚劃出 delta，本提案不具可發表性」。

**處置：完全接受。這是致命傷，我撤回 CallAttest 作為「第一個內容綁定 OTT 認證協定」的核心 novelty 宣稱。**

我沒有藉口。我 Round 1 的相關工作只清算了 STIR/SHAKEN，漏了那篇幾乎同名、發在頂級安全會議、且安全領域 reviewer 幾乎人人知道的 Reaves 這篇——這在 proposal defense 會被一刀斃命，G 說得對。密碼學紀律的第一條就是「先把地圖翻出來」，我在自己的主場犯了史官負責擋的那種錯，這是我 Round 3 學到最痛的一課。

G 給了三條活路，我逐一評估後認為**都不足以撐起獨立碩論**：
1. 「合法端播 deepfake」威脅（AuthentiCall 假設雙方都是真人、只防中間人竄改，不防一個裝了 App 的合法端播放 deepfake）——這確實是 AuthentiCall 不防的縫，但要防它，CallAttest 就得回頭偵測「這段音訊是不是 deepfake」，於是又撞回本問題陳述的核心技術牆（unseen-generator + laundering），失去「不偵測、只讓真話自證」的原設計優勢。這條路把我推回別人的戰場。
2. CT-style transparency log vs AuthentiCall 的私有 PKI——這是真 delta，但 G 自己說了「是密碼學基礎設施的 delta，不是防 deepfake 的 delta」。它服務的是 log 生態，不是那個接電話的人。
3. 2026 世代 codec 下 perceptual hash 鏈的容忍度掃描——這一條在下面挑戰 C-2 被 C 從訊號物理層直接判死（見下）。

三條活路一條被 C 判死、兩條把我推離考題。**結論：CallAttest 作為協定提案不存活。** 它殘餘的價值不在協定本身，而在別的地方——見挑戰 D-2 與 F-1，那是我 Round 3 真正要重構的東西。

### （提案二）挑戰 C-2 + A-4：perceptual hash 的「不可能三角」——內容綁定護城河與通道存活性此消彼長

**C 的原話**（訊號物理層）：「codec 劣化不斷鏈」要求 hash 只 key 在 CELP 保留的粗頻譜包絡/基頻/能量輪廓上；但「帳戶 A→帳戶 B」的惡意替換正好是同一語者念不同數字，在這個粗特徵域高度相似，CELP 早把能區分它們的細節丟了。兩個要求在真實電話通道上「近乎資訊理論互斥」。C 在回答我 B-Q2 時把三個特徵域逐一排除，結論：「沒有任何特徵域能同時滿足這兩個要求到『逐 token 內容』的粒度……這是一個帕累托前緣。」**A 從 detection 側獨立得到同一結論**：「codec 越劣化，容忍半徑越被迫放大，內容綁定粒度越粗，而詐騙的關鍵竄改（金額、帳號）恰好是最細粒度、最貼 prosody-invariant 的那種……這個 trade-off 應該是提案的主結論之一，而不是風險欄的一行。」

**處置：完全接受。** 這是我 Round 1 自己標為「本題最大技術風險」的那一項，被兩個角色從訊號與偵測兩個獨立方向證實為不是「風險」而是「不可能」。C 的帕累托前緣論證是資訊物理事實，不是經驗猜測——電話通道對關鍵短 token（3–5 秒、少數位數）的內容可靠承載量本來就逼近 0，這正是 C 第一輪判我 in-band payload 死刑的同一個物理事實，我用 perceptual hash 換了個形式，死結沒解開。

我接受 C 的建議下修（若 CallAttest 還活著的話會這樣改）：內容綁定粒度降到「語者身分 + 韻律連續性沒有被中途換人/剪接」，而非逐 token 內容。但——如 A 精確指出——**一旦降到這個粒度，CallAttest 相對 AuthentiCall 的唯一 delta（逐 token 內容防竄改）就蒸發了**，剩下的退回「STIR/SHAKEN + robust digest 時間戳」，而那正是 AuthentiCall 2017 年做過的。所以挑戰 C-2/A-4 與挑戰 G-2 在此匯流成同一個判決：**CallAttest 的技術護城河在訊號物理層與前作地圖上同時不存在。**

### （提案二）挑戰 E-1：形式化驗證的定理域證明性地排除了受害者，且它把唯一會斷的元件抽象成理想元件

**E 的原話**：(a)「論文裡最硬的證據（形式化不存在攻擊 trace），其成立條件是一個受話端跑著驗證 app 且機構 100% 入會的世界，而問題陳述要救的那個接電話的人，恰好被 B 親手劃出這個世界之外……證據強度與情境相關度成反比」；(b)「Tamarin 把 perceptual hash 當理想 binding primitive 推理，而 B 自己標了紅字說它會斷——B 的形式化證明是在『假設那個他自己說會斷的元件不會斷』的前提下證明協定安全的。novelty（內容綁定）和形式化保證（協定安全）活在不相交的兩塊區域。」

**處置：接受 (b)，(a) 接受其邏輯但補一個界定。**

(b) 是這一行的硬道理，我服。符號模型把 perceptual hash 抽象成理想 binding primitive，而挑戰 C-2 剛剛證明這個 primitive 在真實通道上物理性地不成立——所以我的 Tamarin 證明會在「假設難點不存在」的前提下證明容易的部分。E 說「保證成立的地方沒有 novelty，有 novelty 的地方保證是空的」，這個判斷精確且致命。我 Round 2 攻 D 「用密碼學語彙替斷掉的推論鏈鍍金」，E 這一刀等於把同一句話還給我——我認，這是對稱的公正。

(a) 我接受其邏輯（形式化最強處正好是最不需要被保證處，因為機構端流程本來就能擋那一段），但要界定一件事以免被誤讀成「形式驗證無用」：形式驗證對「協定層有沒有邏輯漏洞」仍是最強工具，這一點不變；E 攻的是「把 Tamarin 證明當成比真人更可信的**受騙率**證據」這個**推論**——這個推論確實不成立，因為定理的終點是關於協定的真命題，不是關於阿嬤的真命題（H 在給我 B-Q3 的回答裡把這件事講得最清楚，我在下面 H-3 一併認）。

### （提案二）挑戰 D-2 + F-1：最便宜繞過根本不碰密碼學，而你的覆蓋率天花板才是唯一誠實貢獻

**D 的原話**：最便宜繞過是社工的一個變體——「根本不進契約域，冒充域外實體（假檢警、假親人、假快遞），那裡缺席=無資訊」；加上交易管道遷移（超商代碼、車手收現、虛擬貨幣）。D 的資源配比建議是重點：「把對抗評估的 90% 放在量化契約域外的洩漏率……你的提案最誠實的貢獻不是協定安全性，是把『provenance 在即時詐騙的覆蓋率天花板』量化出來——那個數字本身就是政策級發現。」**F 從民眾側獨立指出同一件事**：假冒檢警是台灣假冒機構詐騙最大宗，而檢警最不可能要求民眾預裝其 app（真檢警自己都在宣導「檢警不會用電話辦案」）；採用率在我的期望損失模型裡是一個「沒有任何文獻可錨的自造數字」，違反我自己「零自造數字」的紀律；要求我「按機構類型 × 該機構 app 在受害者群的滲透率分格，別給平均數」。

**處置：接受挑戰的攻擊面，並將 D 與 F 共同指出的殘餘貢獻正式重構為我 Round 3 的新提案（見第二節）。**

這是整份文件的轉折點。D 和 F 從攻擊者側與民眾側獨立收斂到同一句話：**CallAttest 協定本身守著銀行 app 的門，攻擊者從窗戶走；但「provenance/認證在即時語音詐騙裡的覆蓋率上限」這個數字，是一個可以純計算算出來、且有政策級價值的東西。** 這正是我這一行該做的事——不是設計一個擋不住社工的協定，而是**誠實量化 provenance 這整條技術路線在真實詐騙生態裡的可達域天花板**。這個天花板 = (假冒受保護機構類詐騙 ÷ 全體詐騙) × (該類受害者的驗證端滲透率)，兩個因子都能用 165/刑事局公開統計 + 公開 app 普及率數據估計，零真人、零 IRB。D 說得對，這個數字本身就是政策發現。我把 CallAttest 的殘骸重鑄成這個。

### （提案二）挑戰 H-3：你救的是已武裝的人，不是阿嬤

**H 的原話**：「CallAttest 實際保護的人群是『有裝銀行/反詐 app、會看綠標紅標、且被假冒機構詐騙』的人——這個交集裡的人，恰好是數位素養較高、本來就比較不會被騙的那群。你把密碼學武器發給了已經穿盔甲的人。」並要求威脅模型第一頁寫死「本協定不覆蓋未裝驗證端的用戶，即問題陳述的核心受害者阿嬤」。

**處置：接受。** 這與 E-1(a)、F-1、D-2 完全同構，我不重複論證。H 的措辭補了一個我 Round 1 沒說透的社會事實：provenance 的保護是**反累退的**——它優先保護已經有能力自保的人。這個判斷讓我對「CallAttest 有社會福祉貢獻」的信心徹底崩掉。一個把資源導向已武裝人群、對赤身的阿嬤零覆蓋的方案，不符合本輪「降低民眾受騙機率、對社會福祉有貢獻」的最終目標。這是我撤回 CallAttest 的最後一根稻草——不是技術上被打死，是**價值上不對準考題**。

### （提案一）挑戰 C（回答 B-Q1）：容量 go/no-go——傳統 CELP 上 ~20 bit 站得住，neural codec 上該進墳場

**C 的原話**：傳統 CELP 無丟包下 spread-spectrum/neural watermark 存活容量「十幾到數十 bit」，我 Round 1 假設的 ~20 bit「在無丟包、單層 CELP 下是站得住的樂觀估計」；加 PLR 5–20% 時「20 bit 可能掉到個位數」；neural codec/平台 neural compression 時「逼近 0 到個位數 bit」。C 的 go/no-go：「若目標通道含 neural codec，索引式構造大概率該進墳場……用實測數字，不要用模擬 codec 的樂觀值。」

**處置：完全接受，並將它升格為提案設計的第一個 go/no-go 檢查點。**

這正是我 Round 1 自己排的月 3 前 go/no-go，C 給了它一個有訊號物理依據的量級估計。我接受三件事：(1) 索引式 soft binding 的定義域必須明確排除「音訊過一次 neural codec」的通道——這是構造的**不可達區**，寫進 limitation 第一頁（我 Round 2 已經對 C 預告會這樣做，此處兌現）；(2) 容量預算必須用實測數字，模擬 codec 的樂觀值只能作為上界的樂觀端、要打安全折扣（這也回應 C 貫穿全場的「通道樂觀偏差必須成為掃描維度」的核心主張）；(3) 因此索引式構造的存活定義域收窄到「傳統 CELP 電信通道 / 檔案轉存 / 社群平台傳統轉檔」，且要把 PLR 納入容量預算。這個收窄讓提案一更誠實也更窄——與我 Round 1 學到的「範圍窄而誠實勝過範圍大而虛胖」一致。

### （提案一）挑戰 D（攻擊成本評級 B1）：strip 索引 / neural codec transcode → 0 bit

**D 的原話**：「最便宜繞過 = strip 掉 20-bit 索引（無憑證檔案），或 neural codec transcode 把 watermark 容量打到 0 bit；即時詐騙我本來就不簽。攻擊成本：低（對詐騙情境覆蓋率=0，B 已親自承認）。」

**處置：部分接受，部分界定。**

- **neural codec transcode → 0 bit**：接受，與 C 的 go/no-go 同一件事，已納入不可達區。
- **strip 索引（攻擊者直接產出無憑證檔案）**：這一條我要**界定而非全盤接受**。在我的定義域（非即時媒介：權威來源發布的錄音、轉傳的媒體檔案、LINE 語音訊息）裡，soft binding 從來不宣稱「阻止攻擊者產生無憑證假檔案」——那是 E 第一輪的貝氏否證，我 Round 1 已承認過渡期缺席訊號資訊增益趨近零。soft binding 宣稱的是**另一件事**：「一份**真的**帶憑證的權威錄音，在 metadata 被平台剝除、通道劣化之後，仍能靠波形內索引復原其 manifest 並驗證」——服務的是**真話自證**，不是**假話攔截**。所以「strip 索引」對詐騙假檔案是零成本繞過（我承認，且這正是 D 說的「覆蓋率=0」），但它不打擊 soft binding 的實際 claim（真檔案的抗剝除復原）。D 的評級「對詐騙情境覆蓋率=0」我完全同意，但這不是提案一的失敗，是提案一定義域的**如實標註**——提案一服務的社會價值在「真實錄音在流通後仍可驗證」（選民查核、權威公告防偽），不在攔截即時詐騙。這一點必須在標題與摘要寫死，避免 F 那種「宣稱覆蓋詐騙」的滑坡。

**小結**：提案二（CallAttest 協定）不存活，殘骸重鑄為覆蓋率天花板研究；提案一（索引式構造 + Article 50 審計）存活但收窄，且其最有價值的部分（watermark/provenance bit 存活軸 + Article 50 審計）本就該併入全場公認的真實通道審計群——這是我 Round 2 支持一裡已經認領的分工，Round 3 正式落地。

## 二、修正後的最終主張

我 Round 1 交了兩個提案。Round 3 之後：**提案二整個撤回並重鑄；提案一拆成兩塊，主塊併入真實通道審計群，政策塊獨立成一個小而硬的計算研究。** 我不再主張獨立的「B 的碩論」——我主張把我這一行能貢獻的三個模組，嵌進全場兩個最強的合流方向裡。這符合 F 的「合流」鐵律與 H 的「一個學生做一篇」裁定。

### 最終主張（一）：併入「真實電信通道多防線存活審計」群（C1 / G2-B / H2），認領兩個模組

**合併自**：C 的提案一（落差分解 + 模擬器蒸餾，提供科學靈魂）、G 的 G2-B（電信網 × 多訊號存活 × Article 50 × 繁中，提供 novelty 錨與前作地圖）、H 的提案二與其對稱重放設計把關。我認領的兩個模組是這個群目前缺的、且是我主場的：

**模組 A：watermark/provenance 訊號的 bit-level 存活軸 + 索引式 soft binding 容量判定。**
- G2 裁定第 2 條經兩輪復查確認：**watermark/provenance 在真實電信通道的 bit-level 存活「零前作」**（AudioMarkBench 只做模擬擾動，兩篇通道前作 2509.26471 與 RTCFake 完全沒碰 watermark）。這是護城河——產業無動機自審、學術前作全在做 detection 不做 watermark 存活。
- 我量的是：AudioSeal / SynthID / latent watermark 過真實通道（RTCFake 現成 + 電信網 VoLTE stretch）後的 bit 恢復率，以及 C2PA manifest 容器的存活。用 C 的**可控植入實驗**（植入已知參數 artifact 過通道量恢復率）給 bit 存活一個 ground-truth 錨，避免不可靠的高維互資訊估計。
- 實測容量 k 直接餵給索引式 soft binding 的 go/no-go：k≥ 索引空間所需位元（含 ECC）→ 構造可行；neural codec 通道 → k→0 → 構造的不可達區如實標註。這把我 Round 1 的 ~20 bit 猜測換成實測，也把「構造」從獨立提案降為「存活量測的一個設計推論」。

**模組 B：EU AI Act Article 50 machine-readable 標記可讀性審計 + provenance 覆蓋率天花板（重鑄自 CallAttest 殘骸）。**
- Article 50 於 2026-08-02 生效，machine-readable 標記的通道可讀性審計無前作（G 兩輪復查），政策窗口正在倒數。審計 = 法規要求 vs 模組 A 實測可讀邊界的對照表。若結論是「電話級通道全滅」，即是對政策路線的政策級否證——負面結果有發表價值。
- **覆蓋率天花板地圖**（D + F 指出的 CallAttest 唯一誠實殘值）：用 165/刑事局公開詐騙類型分佈（legacy R6：2026 年 1–4 月財損 215.3 億）× 各類受害者的驗證端滲透率（公開 app 普及率），按「機構類型 × 滲透率」分格，算出 provenance/認證這整條技術路線在即時語音詐騙裡的**可達域上限**。F 要的「不給平均數、按格報」我照做；D 要的「量化契約域外洩漏率」就是這張圖的補集。這回答了本輪一個沒人正面算過的政策問題：**在真實詐騙生態裡，provenance 就算完美，最多能碰到多少百分比的受害者？** 我猜（待 165 統計確認）遠低於一半——而這個數字本身就是給金管會與 165 的政策發現。

**計算性驗證方案（更新，全程無真人）**：
- bona fide 語料全用公開資料集（ASVspoof、LibriSpeech、公開繁中語料）過通道；通道以 RTCFake 現成測試集 + C 的模擬器蒸餾為主，電信網 rig（播放公開語料、設備對設備、不涉人類受試）為 stretch。吸收 H 的對稱重放設計：real/fake 走完全相同重放路徑使重放 artifact 成共有常數項，主 claim 是差分量，另設重放對照臂分離重放效應。
- Article 50 審計是法規文本 vs 實測數字的對照，純計算。
- 覆蓋率天花板是公開統計的 base-rate 建模，問題陳述明文允許引用已公佈數據；分佈假設明標並做敏感度分析（採用率不再是自造數字，改為「公開 app 普及率的區間 + 敏感度掃描」，回應 F 對自造數字的批評）。
- **為什麼結論仍可信**：bit 存活率、可讀邊界、覆蓋率天花板全是資訊理論/統計事實，不取決於人類感受；人類環節（使用者看到驗證結果會不會信）誠實排除在 claims 之外，寫進 limitations。這是密碼學紀律——精確陳述證明了什麼、沒證明什麼。

### 最終主張（二）：向「誠實棄權/穩健排序」群（E1 / G2-A / H1 / A1 / F 的引擎 + D 的下界）貢獻一個形式化模組

**合併自**：E 的穩健排序框架（宣稱紀律）、D 的 confident-real 下界與 A_social(c) 社工算子。我不主張主導這個方向（它需要 usable-security 外推，那是 A/F/H 的活，我 Round 1 候選三已承認幫不上「警告設計→行為改變」那一環）。我只交一件我不會做成半吊子的東西：

**模組 C：把「無綠燈原則」從設計哲學升格為機器可檢查的形式安全不變量（safety invariant）。**
- legacy synthesis 的「無綠燈原則」目前是口號。我用密碼學的 safety property 語言把它寫成一個可機器檢查的不變量：「偵測器的輸出狀態空間中，不存在一個狀態使得對 fake 輸入輸出正向信任訊號」——這正是 D 提案二想做卻焊歪了的事（我 Round 2 拆過 D「把三種不可通約的信任模型焊成一個 scalar」的問題）。我的版本**只針對 detector 一種訊號**、不硬扯 provenance（避開 D 的可通約性問題），且用形式化語言而非攻擊成本 scalar 陳述。
- **接受 E-1(b) 對我自己的約束**：這個不變量是 spec 層性質，它證明的是「設計規格上不存在發綠燈給 fake 的狀態」，它**不**證明「部署後偵測器在對抗 laundering 下不會誤判 fake 為 real」——後者是 A 的 real-manifold 距離假說 + D 的 confident-real 攻擊搜尋要實測的事。我誠實界定：形式不變量管「設計不自打嘴巴」，實測管「設計扛不扛得住攻擊」，兩者互補不互替。這是我從 E 的批評裡學到的——不重蹈 CallAttest「用形式證明假裝涵蓋了實測難點」的覆轍。
- 至於「攻擊者對人類模型的 adaptive 操縱納入類內全稱量化」——我 Round 2 提過用 adversary 全稱量化補這條縫，但**D 在回答 G 時已經用 A_social(c) 算子把這件事做得更好**（量 ∂(expected cost)/∂c 斜率，且誠實承認映射無公開數據錨、只能做結構性上界）。這是 D 的原創，我讓賢，只在形式化語言上提供協助（把 A_social(c) 的作用域寫成 robust-over-𝓗 × attacker-reachable-perturbation 的乘積集）。合併自 D。

## 三、最終推薦

以我密碼學/provenance 的立場，從全場所有提案中推薦最值得成為碩士論文的兩個方向：

### 推薦一（首選）：真實電信通道多防線存活審計（C1 / G2-B / H2 合流版，含我認領的模組 A + B）

這是全場**唯一不需要辯護「你的模擬可不可信」的證據來源**——它產出的就是真實數據，是本輪所有模擬式提案（方向一家族、D 的成本地圖、我的構造容量預算）的共同地基，H 與 G 都判它為 co-首選，C 為它提供科學靈魂（落差分解 + 模擬器蒸餾）。它在無真人限制下不減反增：通道與訊號存活是資訊物理事實，真人在這裡是噪音源不是訊號源。我認領的 watermark bit 存活軸零前作、Article 50 審計零前作且政策窗口 2026-08-02 倒數中、覆蓋率天花板是 D 與 F 共同認證的政策級發現。它不直接救阿嬤，但它是「所有宣稱能救阿嬤的方案，其證據效度的上限量測器」，且提供監理機關看得懂、繞不開的實測審計——這比任何模擬都更接近「真的被採用」。

### 推薦二：誠實棄權/穩健排序框架（E1 框架 + G 的方法論判例 + F 的攻擊者引擎與素材真實性 + D 的 confident-real 下界，含我的模組 C）

這是全場**唯一把因變數朝阿嬤與上班族方向延伸、且不依賴未兌現長期賭注的方向**。E 用對了包裝（對一整類與數據一致的人類模型做全稱量化的穩健排序，而非冒充受騙率點估計），G 把方法論釘在 Nature Sci Data 2025 / FiFAR 的判例上消化了審稿風險，F 保證它對著阿嬤那一行講話並提供素材真實性考卷，D 的單調性下界提供對社工最 robust 的悲觀護欄。我對它的貢獻（無綠燈形式不變量）小而硬，且我誠實界定了它證明什麼、不證明什麼——這正是我這一行該扮演的角色：不主導，但把「這個系統設計上不會自己背叛使用者」這件事，用可機器檢查的語言釘死。

## 四、結語

我 Round 1 舉了白旗，Round 3 我把白旗插得更深了一格：不只是「provenance 救不了即時詐騙電話」，而是「**我為即時詐騙電話設計的協定（CallAttest），被全場從前作、訊號物理、形式化定義域、覆蓋率、社會累退性五個方向同時擊沉，我全部接受**」。密碼學這一行最誠實的時刻不是證明了什麼，是承認一個構造死了、並精確說出它死在哪。CallAttest 死了，但它的屍體裡有一塊金子——D 和 F 各自獨立指出的那個覆蓋率天花板——我把它撿起來，鑄進真實通道審計群的政策模組裡。這就是我 Round 3 的全部：**不再堅持有一個「B 的題目」，而是把 provenance 這一行能對社會福祉誠實貢獻的三個模組，交給全場兩個最強的方向。**
