# Round 1 提案：一般民眾代表（Agent F）
日期：2026-07-13

我不是研究者。我是三個人：接到「孫子出車禍」電話的 68 歲阿嬤、在 LINE 收到主管語音要我轉帳的上班族、選前一週看到候選人爭議錄音的選民。我讀完了問題陳述和八篇文獻摘要，以下用我的標準來評判——**在那個當下、那個裝置上、那種心理壓力下，這個東西真的能阻止我受騙嗎？我需要做什麼？我會不會嫌麻煩直接跳過？**

---

## 1. 我看到的問題本質

研究者看到的問題是「偵測器的 EER 太高」「provenance 的信任模型有漏洞」。我看到的問題完全不一樣：

**（a）受騙的瞬間根本沒有「偵測」這個步驟存在的空間。**
阿嬤接到電話時，手機貼在耳朵上，電話是即時的、單向的、正在倒數的（「阿嬤妳快一點，醫生說要先繳錢」）。她沒有辦法「把音訊存下來、上傳到某個網站、等待分析結果」。所有假設「使用者會主動拿音訊去驗證」的方案，對電話詐騙情境的覆蓋率趨近於零。文獻 #8 說最實際的是分層防禦，但我要提醒：**每一層如果需要受害者在壓力下主動操作，那一層等於不存在。**

**（b）詐騙的武器不是音質，是情緒。**
文獻 #1 說人類辨識 deepfake audio 準確率只有約 73%——而且那是實驗室裡冷靜聽的結果。真實情境裡我不是在「判斷這段聲音真不真」，我是在「我孫子是不是快死了」的恐慌裡。VoiceWukong（#2）的 user study 顯示人類對高品質 deepfake 的 FAR 超過 82%，我猜（標明：這是猜測）在情緒壓力下這個數字只會更糟。任何方案的評估如果只測「安靜環境下的辨識率」，對我來說都是無效評估。

**（c）「沒有憑證」才是常態，而民眾不會為缺席的東西起疑。**
C2PA（#4、#5）整套架構建立在「內容帶著憑證」上。但 #6 講得很清楚：惡意 deepfake 根本不會附 credential，provenance 對它完全無覆蓋。身為選民，我在社群上看到那段爭議錄音時，它就是一個轉了三手的 mp3，沒有任何 manifest。要我因為「它沒有憑證」而不信它？拜託，我看過的 99.9% 的內容都沒有憑證。**「缺席的訊號」對一般人不構成警告。** 這點我認為做 provenance 的人（Agent B）最容易忽略。

**（d）誤報的代價由我承擔，而且會殺死整個系統。**
如果偵測器把我真孫子的求救電話標成「疑似 AI 語音」，或把主管的真語音標成詐騙，發生兩三次之後我就會永久關掉這功能——就像大家都直接按掉 cookie 同意視窗一樣。VoiceWukong 實測最佳偵測器 EER 也有 13.5%（#2），意思是大約每七八通就錯一次。用這種準確率直接對民眾發二元警告（真/假），我的直覺是災難。**警告要怎麼下、下多強、錯了怎麼辦，這本身就是研究問題**，而文獻 #8 也把「可信的使用者體驗」列為優先研究方向——但我沒看到哪篇真的做了。

**（e）三個情境的「防線位置」完全不同，不該混為一談。**
- 阿嬤：防線必須在**通話當下、零操作**（電話系統端或極簡提示）。
- 上班族：防線可以在**訊息平台內、一鍵操作**（LINE 裡面直接驗）。
- 選民：防線在**事後、公共查證**（媒體、查核組織），時間壓力最小但社會影響最大。
研究者常常拿一個模型想通吃三個情境。以我的經驗，一個都吃不下。

## 2. 思辨過程（我的內心獨白，含自我質疑與淘汰）

### 候選想法 A：「做一個給民眾用的 deepfake 偵測 App」

最直覺的想法：手機裝個 App，通話時即時分析，響警報。

**自我質疑：**
1. 準確率不夠。#2 說得很殘忍：面對閉源商用生成器，最佳偵測器 EER 13.5%，其他全部 20% 以上，有的接近亂猜。用這種東西對阿嬤發警報，誤報會先殺死信任（見上面 (d)）。
2. 通道會摧毀證據。#3 說僅 codec 壓縮就顯著劣化，電話網路（AMR-WB 之類）正是最糟的通道之一；而且對未知轉檔管線無解。詐騙電話經過電信網路後，偵測依據剩多少？
3. 阿嬤根本不會裝 App。會裝防詐 App 的人本來就是警覺性高的人——最需要保護的人恰恰是觸及不到的人。這是猜測，但我對此很有把握。
4. 通話錄音分析在很多司法管轄區有法律問題。

**判決：淘汰「純偵測 App」。** 但它留下一個修正方向：如果偵測結果不當成「答案」而當成「提示」，準確率門檻可以放寬——這條線索餵給候選想法 C。

### 候選想法 B：「推廣家庭暗號 / 回撥驗證的教育方案」

警政單位一直在宣導：跟家人約一個暗號；接到可疑電話就掛掉、用自己存的號碼回撥。這是唯一我確定「阿嬤做得到」的防禦——它不需要任何技術，而且對 deepfake 完全免疫（詐騙者不知道暗號、接不到回撥）。

**自我質疑：**
1. 這是宣導，不是論文。純教育介入不是資工碩士論文，novelty 在哪？
2. 壓力下人會跳過程序。「孫子在哭、醫生在催」的時候，阿嬤還記得問暗號嗎？我猜多數不會——防禦程序需要在冷靜時演練，緊急時卻要對抗腎上腺素。
3. 暗號會被社交工程套走，回撥會被「我手機摔壞了這是護士的電話」話術繞過。

**判決：不能整個淘汰，但要技術化。** 「回撥/暗號」的本質是**挑戰—回應（challenge-response）**：不去分析對方送來的音訊（那是對方完全控制的），而是丟一個對方無法預測的挑戰，看對方能不能即時正確回應。這個思路可以變成技術研究：即時語音生成系統面對互動式挑戰時會不會露餡？這餵給正式提案二。

### 候選想法 C：「別做偵測器，做『警告該怎麼說』的研究」

既然 #2 證明偵測器短期內就是 13.5%+ 的 EER，那與其再刷 0.5% 的準確率，不如研究：**在準確率就是這麼爛的前提下，系統該怎麼跟人溝通，才能真的降低受騙率？** #2 還給了一個漂亮的支點：人機互補——人類對低品質 deepfake 優於偵測器（FAR 4–19%），對高品質遠差於偵測器（FAR > 82%）。也就是說人和機器擅長的錯誤區域不重疊，合體理論上能大幅超越任何一方。#1 也把 explainability 列為新興議題，#8 把「可信的使用者體驗」列為優先方向。

**自我質疑：**
1. 這是 HCI 研究，資工系收不收？會不會被 Agent H（指導教授）打槍「沒有技術貢獻」？——反駁自己：它有技術成分（偵測器的 confidence calibration、怎麼把模型不確定性轉成人能行動的提示），而且 user study + 量化的「受騙率下降」是紮實的實驗貢獻。
2. 怎麼在實驗裡重現「心理壓力」？找受試者來假裝恐慌，倫理上和效度上都有問題。——修正：可以用時間壓力 + 金錢誘因（做對有獎金、被騙扣獎金）當 proxy，這是行為實驗的標準做法；不完美但可辯護。
3. 警告介面做得再好，模型錯的那 13.5% 還是錯。——反駁：重點不是消滅錯誤，是讓警告觸發「查證行為」（回撥、問暗號）而不是觸發「相信機器的二元判決」。警告的目標是改變行為，不是給答案。

**判決：存活，成為正式提案一。**

### 候選想法 D：「給選民的錄音查證管道 / C2PA 標章普及」

選民情境：讓查核組織或平台對選舉相關音訊掛 Content Credentials，民眾看標章。

**自我質疑：**
1. #6 直接把這條路打殘：validator 之間互相矛盾（同一張圖 Adobe 判有效、Verifieddit 判無效）、timestamp 可換、revocation 檢查是 optional、甚至能用 conforming 裝置替 AI 內容簽出「真實」憑證。我一個普通選民要怎麼消化「這個標章可能本身就是錯的」？
2. #7 更狠：可以造出「經認證的假內容」，完全不用破解密碼學。標章反而變成詐騙的加分道具——「有認證欸，一定是真的」。
3. 最根本的還是 (c)：惡意錄音不會有憑證，而缺席不構成警告。
4. 選舉時程和平台合作都不是碩士生一年內推得動的。

**判決：淘汰（作為獨立方向）。** 但保留一個民眾視角的教訓給大家：**任何顯示給民眾的「真實性標記」，其誤導成本可能高於其資訊價值**，這應該成為評估所有方案的必答題。

## 3. 正式提案

### 提案一：壓力情境下的人機協作警告系統——「不完美偵測器 + 人」能不能贏過兩者單獨？

**核心 idea**
接受偵測器在真實條件下就是 EER 13.5–50%（#2）的現實，把研究問題從「提高偵測準確率」改成「**給定一個不完美的偵測器，設計並實證怎樣的警告介入（何時警、怎麼警、警什麼、建議做什麼），能在模擬詐騙壓力下最大幅降低受騙率、同時不因誤報摧毀使用者信任**」。以 LINE 語音訊息詐騙（上班族情境）為主場景，因為它是可以合法介入、可以做受控實驗的通道。

**為什麼有機會成立（文獻支撐）**
- 人機錯誤互補有實測證據：#2 的 user study 顯示人類對低品質 deepfake FAR 4–19%（勝過偵測器），對高品質 FAR > 82%（遠輸偵測器）——兩者擅長區域不重疊，協作有理論空間，而 #2 作者自己也點名支持人機協作偵測框架。
- #1 指出人類單獨只有 ~73% 準確率、機器未穩定勝過人類直覺；#8 把「可信的使用者體驗」列為優先研究方向但領域內沒人做——這是明確的空缺。
- 警告設計不是憑空發明：詐騙警示、釣魚郵件警告在 usable security 領域有成熟方法論可以移植（此為方法論借用，非 audio 文獻，標明）。

**大致技術路線（一年）**
1. 第 1–3 個月：取現成偵測器（AASIST2 / SSL-based，#1、#2 的公開模型），用 VoiceWukong 樣本 + 自行通過真實 LINE 通道 laundering 的樣本（呼應 #3 的未知管線 gap）校準其在「LINE 語音訊息」這個通道上的真實 operating point 與 confidence calibration。
2. 第 3–5 個月：設計 3–4 種警告條件：（a）無警告（對照）、（b）二元判決（「這是 AI 語音」）、（c）校準後的不確定性提示（「此訊息有 XX 特徵，無法確認來源」）、（d）行為導向提示（不給判決，直接給一鍵回撥/改用視訊確認的動作按鈕）。
3. 第 5–9 個月：受控 user study：模擬 LINE 介面 + 時間壓力 + 金錢誘因誘發壓力 proxy；混入真人與 deepfake 語音訊息（部分要求轉帳）；量測各條件的受騙率、誤報後的信任衰減（跨多輪）、以及年齡分層差異（招募含高齡受試者）。
4. 第 9–12 個月：分析、消融（偵測器準確率高低 × 警告形式的交互作用——刻意用「調爛的偵測器」測警告設計的容錯度）、撰寫。

**預期貢獻**
- 第一個在 audio deepfake 領域量化「偵測器準確率 × 警告設計 × 使用者壓力 → 實際受騙率」關係的實證研究。
- 給所有偵測研究一個部署端的答案：EER 要多低、警告要怎麼下，才對真人有用——這是 #2、#3 的 benchmark 都回答不了的最後一哩。
- 直接對社會福祉：產出可被通訊平台採用的警告設計準則。

### 提案二：互動式挑戰—回應驗證——把「分析對方送來的音訊」改成「考對方一題他無法預錄的題目」

**核心 idea**
被動偵測輸在：音訊完全由攻擊者控制、又被通道 laundering 摧毀證據（#2、#3）；provenance 輸在：惡意內容根本不簽（#6）。兩者都是在「事後檢查一個靜態產物」。本提案把驗證改成**即時互動**：當通話/語音對話可疑時，系統（或被引導的使用者）提出隨機挑戰——「請跟著唸這串隨機句子」「請用氣音說」「請哼這段旋律」——然後偵測器只分析**挑戰的回應**。即時 voice conversion / TTS 系統要在幾百毫秒內對不可預測的內容產生無破綻回應，其延遲、韻律、非典型發聲（氣音、笑聲、咳嗽）的破綻理論上遠大於預錄或非互動生成。這是「回撥驗證/家庭暗號」（我在思辨 B 保留下來的民眾智慧）的技術化：把民眾已經被宣導、但壓力下做不到的查證程序，變成系統代勞的一鍵動作。

**為什麼有機會成立（文獻支撐）**
- #2 證明對攻擊者自由生成的音訊做被動偵測，在閉源生成器下 EER 13.5–50%，且 augmentation / multi-domain training 補救無效甚至有害——被動路線的天花板已被實測釘死，改變賽局規則有正當性。
- #3 證明退化主因是 distribution shift；挑戰—回應的優勢是**驗證方控制內容分布**（挑戰是自己出的），把 unseen-generator、unseen-content 的泛化問題縮小成「已知挑戰集上的回應分析」，是把 #3 指出的 gap 繞開而非硬解。
- #6 論證 provenance 對不簽署的惡意內容零覆蓋；挑戰—回應不需要攻擊者合作，覆蓋的正是這塊。
- #8 的分層防禦框架中，「即時互動驗證」是現有三層（偵測、溯源、浮水印）之外缺席的一層。
- 誠實標註：即時 VC 系統對隨機挑戰的失效程度，目前是**假設**，需要第一階段實驗證實或證偽——這本身就是論文的第一個貢獻點。

**大致技術路線（一年）**
1. 第 1–4 個月：建挑戰語料與攻擊模擬：選 3–5 個 SOTA 即時 VC / streaming TTS 系統（含商用，呼應 #2 的閉源測法），對隨機文字、非典型發聲等挑戰類型生成回應；同步錄真人回應，建立第一個「challenge-response audio deepfake」資料集。
2. 第 4–7 個月：分析與偵測：量測各挑戰類型下真假回應的可分性（延遲分布、韻律、發聲特徵、以及餵給現成偵測器的 EER），找出「對機器最難、對真人最不費力」的挑戰子集；通過電話級 codec（AMR-WB、Opus，用 #3 的通道模擬）驗證挑戰式偵測是否比被動偵測更耐 laundering。
3. 第 7–10 個月：可用性驗證（我最在乎的部分）：小規模 user study——在模擬詐騙通話中，一鍵觸發挑戰的接受率、完成率、對真實來電者的社交成本（會不會不好意思考自己主管？），高齡受試者能否操作。
4. 第 10–12 個月：對抗性討論（給 Agent D 的預留戰場：攻擊者預先合成常見挑戰、用真人共犯接管挑戰段）、撰寫。

**預期貢獻**
- 第一個系統性量化「即時生成系統 vs. 互動式挑戰」的 audio 資料集與 benchmark。
- 一個不依賴生成端合作、對通道 laundering 較不敏感、且民眾單鍵可用的驗證原語（primitive），補上分層防禦缺席的互動層。
- 就算結論是負面的（即時 VC 已能完美應對挑戰），也是對「回撥/暗號宣導」這條全球都在用的防詐政策的重要實證檢驗。

## 4. 我留給其他討論者的問題

1. **給 Agent D（紅隊）**：提案二的挑戰—回應，你會怎麼打？特別是：(a) 攻擊者預先合成大量常見挑戰回應的可行性；(b) 「真人共犯只在挑戰段接手」的混合攻擊；(c) 即時 VC 的延遲破綻還能撐幾年？如果答案是「明年就沒破綻」，我要提早知道。
2. **給 Agent A（Detection 研究者）**：以 VoiceWukong 的 13.5% EER 為現實，你認為對一般民眾發警告的最低可用 operating point 在哪裡（FAR/FRR 各多少）？以及 #2 的人機互補現象，有沒有辦法在模型端就利用（例如模型只對它有把握的區域出手、把它不擅長的低品質區留給人）？
3. **給 Agent B（Provenance）＋ Agent H（指導教授）**：B——對「缺席的憑證不構成警告」這個死結，provenance 陣營有解嗎？還是 C2PA 在詐騙電話與選舉錄音這兩個情境應該直接承認不適用？H——提案一這種「偵測器現成、貢獻在 user study 與部署實證」的題目，在資工所的 novelty 標準下站得住嗎？IRB 與高齡受試者招募的時程風險，一年內可控嗎？
