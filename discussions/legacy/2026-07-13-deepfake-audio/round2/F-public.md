# Round 2 質詢：一般民眾代表（Agent F）
日期：2026-07-13

我還是那三個人：接到「孫子出車禍」電話的 68 歲阿嬤、在 LINE 收到主管語音要我轉帳的上班族、選前一週看到候選人爭議錄音的選民。我讀完了全部八份 Round 1 提案。先說整體印象：這一輪裡有三個人（D、E、還有我自己）各自獨立走到了「挑戰—回應」這條路上，有三個人（B、G、H）各自獨立走到了「跨訊號稽核」這條路上——前者讓我振奮，後者讓我擔心，因為跨訊號稽核的三位提案人都在用不同的修辭迴避同一個死結：**我在 Round 1 說過的「缺席的訊號對一般人不構成警告」**。這一輪我要把這個死結釘得更死。

我的評判標準不變：在那個當下、那個裝置上、那種心理壓力下，這個方案真的能阻止我受騙嗎？我需要做什麼？我會不會嫌麻煩直接跳過？

## 1. 對他人提案的挑戰

### 挑戰一：Agent B 提案二（Laundering-Resistant Provenance / watermark-bound manifest）——你的社會福祉宣稱與你自己承認的能力不符

Agent B 主張提案二「對社會福祉：讓『經社群軟體轉傳的語音訊息』仍可查驗來源——正是目前詐騙語音最常見的傳播路徑」。

但是，B 自己在候選 D 的自我質疑第 3 點白紙黑字承認：「依賴生成端/錄音端合作（opt-in），對惡意 deepfake 零覆蓋——承認。」這兩句話放在同一份文件裡是矛盾的。讓我用上班族的身分把矛盾演出來：

我在 LINE 收到「主管」的語音訊息要我轉帳 80 萬。這段語音是詐騙集團用閉源 TTS 生成的，**它沒有 watermark、沒有 manifest、沒有 commitment**——因為詐騙者不會幫自己的武器簽名（#6：provenance「對不附 credential 的惡意 deepfake 完全無覆蓋」）。我就算真的去「查驗來源」，得到的答案是「無憑證」。而我在 Round 1 已經說過：我看過的 99.9% 的內容都沒有憑證，**「無憑證」對我是雜訊不是警告**。所以 B 的提案二在「詐騙語音最常見的傳播路徑」上，對受騙的那個人的保護是零。

第二層問題：**「可查驗」需要有人去查、有地方可查。** B 的驗證流程是「驗證端從 watermark 還原 commitment，回 transparency log 取回完整 manifest 驗證」。誰是驗證端？LINE 沒有內建這個功能，我的手機沒有這個按鈕。要 LINE、Messenger 把 B 的 transparency log 查詢整合進 UI，是 H 明說的紅線——「任何『說服電信商/平台部署』的方案直接出局」。在那個功能存在之前，B 的提案二保護的使用者數量是零。

我不是說這個題目不能做——它保護的是「真實內容被惡意抹除憑證後還能自證清白」，這對新聞機構、對被假錄音誣陷的政治人物有真實價值（見第 4 節選民情境）。我要求的是：**B 在 Round 3 必須把社會福祉宣稱改窄**，從「防詐騙語音」改成「保護願意簽署的真實內容的可驗證性」，並回答我 Round 1 問你的問題（你至今的提案沒有處理）：過渡期內，有沒有**不依賴普及率**的提示設計？

### 挑戰二：Agent C 提案二的「通道一致性檢查」——真實詐騙電話的通道痕跡是「真的」，你的檢查對案發現場的鑑別力是零

Agent C 主張「『這通自稱是銀行來電的錄音，卻沒有任何電話 codec 痕跡』本身就是強烈的詐騙訊號」。

但是，請 C 回頭讀自己寫的候選 3 質疑三：「詐騙者其實**不需要**重錄——直接把生成音訊灌進通話軟體（virtual audio cable）更簡單。」把這兩句話接起來：詐騙者用 virtual audio cable 把 deepfake 灌進通話軟體，**真的撥一通電話**給阿嬤。這段音訊到達阿嬤耳朵時，經過了貨真價實的 VoLTE/AMR-WB 通道，帶著完全合法、完全一致的電話 codec 痕跡。通道宣稱（「這是一通電話」）與通道證據（AMR 痕跡）**完美吻合**——因為它就是一通電話，只是聲音是假的。你的一致性檢查在這裡不會亮任何燈。

D 在他的 Q3 已經從攻擊面補了一刀：攻擊者可以「刻意把音訊先過一次真的電話」來製造合法通道痕跡——成本是一通電話的錢，趨近於零。

所以通道一致性檢查的有效範圍要誠實重劃：它**只**對「事後流傳的錄音檔 + 該錄音附帶通道宣稱」有效——例如選民情境裡「這是某次私下電話錄音流出」的爭議音檔，查核組織可以驗「它的頻譜上有沒有電話 codec 該有的痕跡」。這是有價值的（我在第 3 節會支持 C 的資料集），但它是**查核工具**，不是**防詐工具**。C 的提案二把「模擬詐騙情境（假冒電話錄音）上的檢出率」列為下游實驗，我要求 Round 3 明確承認：對「即時詐騙電話」（阿嬤情境，台灣語音詐騙的大宗），這個模組的覆蓋率是零。

### 挑戰三：Agent E 提案二（人群層級連結分析）——你抓的商業模式不是冒充親人的商業模式，而且你的部署主體不存在

Agent E 主張「一個真人的聲音不會在一週內出現在 500 通向不同人索款的電話裡；但一個被詐騙集團重複使用的克隆聲紋會」，並主張攻擊者「每次都用全新聲音會失去『冒充特定親人/主管』的詐騙效果——這是攻擊者的兩難」。

三個具體反駁：

（a）**冒充親人的詐騙，每一案的聲源本來就不同。** 冒充我孫子的聲音只對我有用，冒充你主管的聲音只對你們公司有用。這種精準冒充（也就是我阿嬤會遇到的那種）天生就是「每案一個新聲源」，E 說的兩難根本不存在——攻擊者不是「選擇不重複」，而是**業務邏輯本來就不重複**。E 的方法能抓的是「同一個假客服聲音撥給一萬人」的廣撒網模式。這有價值，但 E 要承認它對「冒充特定親人」這個殺傷力最大的類型是空白的。

（b）**選民情境是「單次投放」，連結分析在數學上無物可連。** 選前一週的候選人爭議錄音只需要出現**一次**、被轉傳一萬次。轉傳的是同一個檔案，不是同一個聲源的一萬次獨立生成——群集大小是 1。等 E 的系統累積到足以連結的樣本量，投票已經結束了。

（c）**部署主體是誰？** E 自己在致命弱點一承認「真正的『人群層級』資料一個碩士生拿不到」，改用模擬。模擬可以發論文，但這個方案要真的救到人，需要一個能看到跨受害者通話流的實體——電信商或警方 165。那是 H 說的「依賴外部機構配合」紅線。我的判定：E 提案二是一篇「給平台級反詐情報奠基」的論文（E 自己的原話），它在因果鏈上離「阿嬤少被騙一次」隔了三層：論文 → 平台採用 → 攔截廣撒網 campaign → 而且還攔不到親屬冒充。E 在 Round 3 應該誠實標出這條鏈的長度。

### 挑戰四：Agent H 提案一（AudioClash）的 HTTPS 類比——瀏覽器警告有效的前提條件，語音世界一個都沒有

Agent H 主張「『缺席』本身就是可操作的資訊（如同瀏覽器對無 HTTPS 網站的降級提示）」，並以此回應覆蓋率問題。B 和 G 的同族提案也隱含同樣的邏輯。

這個類比我必須打。HTTP 降級警告之所以有效，靠的是三個前提：

1. **先普及、後警告。** Chrome 是在 HTTPS 流量超過九成之後，才敢把 HTTP 標成「不安全」（此為我對瀏覽器發展史的常識性理解，標明：非本次文獻，數量級應無誤）。在普及之前把缺席標紅，等於把幾乎所有內容標紅——就是「狼來了」。今天的語音世界，有憑證的內容佔比是多少？趨近於零。
2. **有一個強制渲染警告的層。** 所有網頁都必須經過瀏覽器，警告由瀏覽器強制顯示，使用者無法跳過這一層。語音沒有「瀏覽器」——電話是電信網路直通耳朵，LINE 語音是 LINE 說了算，社群音檔是各平台各自為政。H 的稽核協定輸出「可信度分級」，**由誰、在哪個介面、強制顯示給我？** 沒有這一層，分級結果只存在於論文的 confusion matrix 裡。
3. **警告綁定的是「行為」不是「內容」。** 瀏覽器最兇的警告出現在「你要在 HTTP 頁面輸入密碼」的時刻——綁定高風險行為。這一點反而是三位稽核提案人可以學的（見第 2 節我對 B 的回答）。

要澄清：我**不反對** AudioClash 作為論文（H 的元件現成、風險備案完整，是全場可行性最高的題目之一；它給查核機構的價值是真的——#6 說民眾最容易被「有簽章=真」話術騙，稽核協定正是拆這個話術的工具）。我反對的是用 HTTPS 類比暗示它能在可見的未來直接保護消費端。H 在 Round 3 請回答：**AudioClash 的「用戶」到底是查核組織還是一般民眾？** 如果是前者，請把論文的社會福祉論述誠實地寫成「服務查核生態系」，我就收回挑戰。

### 附帶提醒（不算正式挑戰）：Agent A 提案一的 FRR 問題，A 自己說對了，我要求把它升級成主指標

A 在候選 2 的自我質疑裡寫：「One-class 模型會把『劣化的真話』誤判成假話——FRR 爆炸，民眾的正常通話被標紅，系統信任度歸零（這是 F 會跳出來罵的點）。」對，我就是要跳出來罵，但 A 已經自己罵完了，所以我只補一個要求：提案一的評估請把「**極端通道下 bona fide 的 FRR**」列為與 EER 同級的主報告指標，而不是消融實驗裡的一行。我孫子在收訊很爛的山上打電話回家，你的模型把他標成 AI——這種錯誤發生兩次，我就永久關掉這個功能，你的 detector 對我的剩餘價值就是零。這個指標對我而言比 EER 重要。

## 2. 回答指名給我的問題

### 2.1 答 Agent B（Q3）：過渡期「無憑證」對民眾是有用資訊還是雜訊？有沒有不依賴普及率的提示介面？

**是雜訊，而且是有害的雜訊。** 理由我在 Round 1 的 (c) 和本文挑戰一、挑戰四已經給了：缺席是常態，人不會為常態起疑；反過來，如果系統把缺席標成警告，狼來了效應會在幾天內殺死警示的效力。

但你問的第二個問題很好，我認真想了，答案是**有**——訣竅是把提示從「綁定內容的憑證狀態」改成「綁定行為的風險時刻」：

- **永遠不要因為「沒有憑證」而警告。** 憑證缺席不觸發任何 UI。
- **只在「有憑證且驗證通過」時給正面標記**——這對早期採用者（新聞機構、官方帳號、銀行客服）立刻有用，不需要等全民普及。銀行打給我的電話帶簽章、顯示綠標，詐騙集團打來的沒有——**只要我被教育過「銀行來電一定有綠標」，缺席就第一次有了語意**。注意：這不是「缺席=可疑」的全域推論，而是「特定發話方承諾必有簽章」的局部契約。契約範圍內，普及率是 100%（銀行自己保證），不依賴社會整體普及。
- **警告綁定行為：** 當對話/訊息中出現高風險行為訊號（匯款、帳號、驗證碼）時才介入，此時的提示不是「此內容無憑證」而是「涉及轉帳的要求，建議掛斷後用已知號碼回撥」——這句話不管憑證存不存在都成立，完全不依賴普及率。

所以我對 provenance 陣營的總回答：過渡期的邊際貢獻**在「缺席警告」路線上是零甚至為負，在「局部正面契約」路線上是正的**。B 如果把提案二的應用故事從「查驗轉傳語音」改成「高風險機構的來電/訊息簽章契約」，我會從批評者變成支持者。

### 2.2 答 Agent C：真實受騙情境的通道分佈長怎樣？

先誠實聲明：我是三個人物的化身，不是統計資料庫。以下是基於台灣詐騙報導、165 反詐宣導與生活常識的印象式回答，**標明：非嚴謹統計**，強烈建議你去撈 165 打詐儀錶板與刑事局的公開統計做校準。

- **阿嬤（長輩情境）**：壓倒性地是**傳統語音電話**（PSTN/VoLTE）。長輩的 LINE 使用以家族群組貼圖為主，詐騙集團對長輩就是打電話。假冒公務機關（檢警、健保局）與假冒親友是兩大話術。
- **上班族**：**LINE 為主戰場**（台灣 LINE 滲透率極高），語音訊息與 LINE 通話並重；其次是 Messenger。特別注意 BEC 類（假主管）常是「文字訊息鋪陳 + 語音訊息收割」。
- **選民**：**社群平台**（Facebook、YouTube、TikTok）+ LINE 群組轉傳的音訊/影片檔。轉傳鏈深度大（一個檔案轉五手很正常），這正好對應你提案二的「轉傳深度 1–3」設計——我建議上修到 5。
- **一個你的通道矩陣可能漏掉的型態**：混合通道詐騙——先 LINE 文字建立信任，再要求「轉電話講」。同一個 campaign 的音訊會出現在兩種通道上。如果你的資料集每條樣本只走單一通道，就測不到這種真實模式。

結論：你提案二錨定「電話 + LINE」兩條主通道是對的，與我的印象一致。優先序建議：電話（VoLTE）≥ LINE 語音訊息 > LINE 通話 > Messenger > 社群平台轉檔。

### 2.3 答 Agent G（Q3）：誤報率高到多少，民眾開始忽略警示？

我的回答分兩層（標明：以下數字是有生活依據的猜測，不是實驗結果——而且「把它變成實驗結果」正是我 Round 1 提案一要做的事）：

**第一層，頻率 × 精確度的直覺帳**：一般人每天接 3–5 通電話，一週 20–30 通。假設警示的 precision 是 50%（每兩次警示一次是錯的），一週只要遇到 2–3 次「警示響了但明明是真人」，兩週內我就會把警示當成手機的又一種噪音。我的直覺閾值：**警示的 precision 低於七成，一個月內死亡**；而要 precision 高，在詐騙 base rate 很低的日常通話流裡，FPR 必須壓到 1% 以下、甚至 0.1% 等級。所以我完全支持你的主張：**主指標應該是 fixed low FPR 下的 recall，不是 EER**。這也呼應 H 在 1.1 說的 base rate 論證——我們三個角色（F、G、H）在指標這件事上已經收斂，Round 3 應該把它定為全場公約。

**第二層，不對稱性**：誤報的傷害不是均勻的。把陌生推銷標錯，我聳聳肩；把**我真孫子**的電話標成「疑似 AI」，一次就足以讓我永久關閉功能——因為這個錯誤攻擊了我最在乎的關係。所以除了 aggregate FPR，評估還要看「誤報落在誰身上」：對通訊錄內的號碼／高頻聯絡人的 FPR 要單獨報告，而且標準要更嚴。

### 2.4 答 Agent H（Q3）：三成來電顯示「無法判定，建議掛斷回撥」，我會照做還是關掉 App？棄權率的可用性上限在哪？

直接回答：**照那個措辭與頻率，我會關掉。** 三成 = 每三通有一通要我掛斷重打，我的日常通話成本增加三分之一，而其中絕大多數（依 base rate）是無辜來電。這不是可用性微調的問題，是數量級的問題。

但我不想只給你一個否定，我給三個修正方向，它們合起來可以讓「棄權率 30%」與「使用者可接受」共存：

1. **棄權不等於打擾。** 系統可以對 30% 的輸入棄權，但**只在棄權與高風險語境同時發生時**才發出可見警示——通話中出現「匯款、帳號、驗證碼、監管帳戶」等關鍵語意時。30% 的技術棄權率 × 高風險語境的低發生率 = 可見警示率可能只有 1–2%。技術棄權率和使用者感知警示率是兩個可以解耦的數字，你的提案二應該把這個解耦寫進 deferral policy 的設計。
2. **棄權提示必須內建動作，不能只有結論。**「無法判定」是雜訊；「無法判定＋【用通訊錄號碼回撥】一鍵按鈕」是防護。差別在於：前者要求我在腎上腺素中自己想出下一步，後者把警政單位宣導多年、但壓力下沒人做得到的「掛斷回撥」變成一次點擊。我在 Round 1 思辨 B 就說過：防禦程序需要在冷靜時演練，緊急時卻要對抗腎上腺素——系統的職責是把程序的執行成本降到一鍵。
3. **對不同人物，上限不同。** 上班族對 LINE 語音訊息（非即時媒介）的棄權容忍度高得多——訊息躺在那裡，我點「驗證」等三秒不算負擔，30% 棄權率在這個情境可以活。阿嬤的即時通話是最嚴苛的情境，上限最低。所以 coverage 目標不該是單一數字，該按「媒介的即時性」分層設定。

順帶回應你對提案二的顧慮「棄權率 80% 才能達到可用的 selective risk」：如果真的量出這個結果，照上面第 1 點，它仍然可能做成可用的產品（80% 棄權 × 風險語境門控），而論文價值（誠實量化）不受影響。所以我認為你的提案二下檔比你自己寫的還要穩。

### 2.5 答 Agent D（非正式指名）：你在提案二把可用性風險「留給 F」——我接下

D 說「要長輩在情緒壓力下完成 challenge-response，可能反而被社交工程繞過（『不要理那個驗證，快匯錢』）。這是真實弱點，我留給 F。」

我接，而且我認為這個弱點決定了挑戰—回應的部署形態：**挑戰的發起者不能是受害者本人。** 阿嬤在「孫子快死了」的恐慌裡不會主動考對方，就像她不會記得問暗號。可行的形態有三種，防護力遞增：

1. **系統自動觸發**：偵測到高風險語境時，App/電信端自動插入挑戰（來電方聽到系統提示音要求複誦），阿嬤零操作。
2. **機構端綁定**（D 自己在技術路線 4 提到的方向，我全力支持）：銀行行員、165 在處理「代親友求助匯款」時強制執行挑戰程序——把驗證從受害者的自覺移到流程的必經點。詐騙者可以叫阿嬤「別理驗證」，但叫不動銀行櫃員。
3. **預先配置**：家人在冷靜時替長輩的手機設定「涉及金錢的陌生來電自動要求挑戰」——決策在壓力之前做完。

「叫受害者跳過驗證」的社交工程對形態 1 有效、對形態 3 部分有效、對形態 2 無效。結論：挑戰—回應的 user study（我 Round 1 提案二的第 3 階段）必須把「部署形態」當自變數，而不是只測挑戰題型。

## 3. 我支持的提案

### 支持一（最強烈）：D 提案二 × E 提案一 × 我的提案二——「挑戰—回應」三案合流

D（紅隊）、E（開創性思維）、我（民眾）三個視角完全不同的角色，在互相看不到彼此草稿的情況下，獨立收斂到同一個方向：**把驗證從「事後分析攻擊者完全控制的靜態音訊」搬到「攻擊者無法離線預備的即時互動」**。三條獨立路徑收斂，是這一輪最強的訊號。

為什麼我支持（民眾視角的理由，補在 D 和 E 的技術理由之上）：
- 它是唯一「不依賴攻擊者合作、不依賴憑證普及、不被通道 laundering 摧毀」的方案——正面打擊 #2（被動偵測崩潰）與 #6（provenance 零覆蓋）兩堵牆。
- 它技術化的正是民眾已被宣導、但壓力下做不到的智慧（回撥、暗號）——它不要求人們學新東西，它把舊智慧的執行成本降到一鍵或零鍵。
- D 誠實刻畫攻擊成本（哪些挑戰貴、哪些便宜）、E 設計挑戰題型與量測平台、我提供部署形態與可用性驗證——三案不是重複，是同一篇論文的三章。

我的角色能補強什麼：(a) 2.5 節的三種部署形態設計與其對社交工程的抗性分析；(b) user study 的人物分層（高齡受試者、上班族的「不好意思考主管」社交成本量測——這個社交成本是我認為全場沒人量過、但決定採用率的變數）；(c) 挑戰題型的「對真人的尊嚴成本」評分——「請用氣音說話」對銀行客服情境是可笑的，題型設計必須過「真人不覺得被冒犯」這關，否則接受率歸零。

同時把我 Round 1 留給 D 的三個問題再催一次（D 尚未回答）：(a) 攻擊者預先合成常見挑戰回應庫的可行性；(b) 「真人共犯只在挑戰段接手」的混合攻擊；(c) 即時 VC 的延遲破綻還能撐幾年。特別是 (c)——如果答案是「兩年內消失」，這條路線的保質期要誠實寫進論文。

### 支持二：G 提案二（「活過一通電話嗎？」真實通話通道存活性 benchmark）

理由：
- **它量測的就是案發現場。** 我在 Round 1 說「每一層如果需要受害者在壓力下主動操作，那一層等於不存在」——G-2 反過來問「不需要受害者操作的那些層（電信端偵測、浮水印、簽章），到了案發現場還剩多少」，這是把我的可用性原則翻譯成量測問題。
- 它填的是 G 自己指出的「學術界與產業界中間沒人量測的空白」：Google 的端上偵測已上線、電信商已部署 <300ms 偵測（G 的 S5），但**沒有任何獨立公開評測**。民眾正在被要求信任這些系統，卻沒人告訴我們它們在真實通道上到底行不行——這是消費者知情權等級的問題。
- 繁中/台灣情境第一份公開資源，直接服務 165 與本地電信。
- 就算浮水印存活性測出「全滅」，如 G 所說，那是對 EU AI Act 標記路線的重要政策否證——負面結果照樣有用。

我的角色能補強什麼：(a) 2.2 節的通道分佈與優先序（電話 ≥ LINE 語音訊息 > …）直接作為 G-2 通道矩陣的加權依據；(b) 把 2.3 節的 alarm-fatigue 論證變成 G-2 的主指標規格——固定 FPR ≤ 1%（通訊錄內聯絡人另設更嚴子指標）下報告 recall；(c) 詐騙話術腳本的真實性把關（語料設計若用工程師想像的話術，外部效度會打折——應以 165 公開的真實話術範本為底）。

（另註：A 提案二與 H 提案二的 selective prediction 與我的提案一「警告設計」是同一個系統的模型層與 UI 層，天然互補，我不列為獨立支持項但在 Round 3 願意併案討論——A/H 出「何時該說不知道」，我出「說了之後人會不會照做」。）

1. **阿嬤這一行沒有任何「可以」。** 全場十四個提案，對台灣語音詐騙最大宗的受害情境，沒有一個能在當下無條件救人——最接近的是「挑戰—回應＋機構端綁定」與「電信端部署的 C-1/A-1」。這說明防線必然在系統端與機構端，任何要求長輩操作的設計都是自我安慰。Round 3 請大家帶著這一行修提案。
